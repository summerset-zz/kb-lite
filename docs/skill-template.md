# kb-lite 知识库

一个**只读**的本地知识库服务。它把用户磁盘上的 markdown 目录切成了「条目（一篇文件）→ 章节」两级结构。

服务地址：`{{BASE_URL}}`
鉴权：{{AUTH_NOTE}}

## 先看有哪些知识库

库列表**不写在这份文档里**。这份文档是装在你目录里的一份文件，不会随用户的操作自动更新；
把列表写进来，用户每添一个库它就过期了。**每次会话先取一次**：

```bash
curl -s {{AUTH}}"{{BASE_URL}}/kb"
```

```json
{ "ok": true, "kbs": [
  { "name": "我的笔记", "entries": 128, "sections": 743, "bytes": 2201398,
    "rootPath": "D:\\notes", "updatedAt": 1762473600000 }
] }
```

- `name` 就是下面路径里的 `{知识库}`。中文名字要做 URL 编码（`我的笔记` → `%E6%88%91%E7%9A%84%E7%AC%94%E8%AE%B0`）。
- 列表为空，说明用户还没添加知识库：告诉用户去 kb-lite 界面上加一个，**不要自己去找目录**。
- `rootPath` 是这些文件在磁盘上的实际位置。只有要**写**文件时才用它（比如用户让你把资料整理进去）。

## 三条铁律

1. **先搜再读，不要一上来读整篇。** 搜索只返回候选（标题 + 摘要 + 目录），正文要按目录里的编号单独读一节。
2. **一次把多个说法一起搜。** `q` 可以给多个（最多 5 个）：同一件事的不同叫法、中英文、简称全称，一次都放进去，**不要为此重复调用**。
3. **内容可能不是最新的。** 这是某个时间点的切片快照。回答里如果依赖具体细节，说明「根据知识库（截至 …）」。

## 搜索

```bash
curl -s {{AUTH}}\
  "{{BASE_URL}}/kb/{知识库}/search?q=部署流程&q=deploy&limit=5"
```

返回样例：

```json
{ "ok": true, "results": [
  { "title": "运维手册", "path": "ops/runbook.md", "rev": "a1b2c3d4", "score": 42,
    "summary": "线上环境的操作手册。",
    "toc": "1 上线流程 · 1203 字\n2 回滚 · 空\n  3 快速回滚 · 380 字" }
] }
```

- `limit` 默认 5，最多 10。
- 结果少不要紧，`score` 低不代表不相关；**没有结果才说明该换词**。

## 怎么读 `toc`

每一行是 `<编号> <标题> · <字数>`：

- **行首那个数就是章节编号**，读正文时原样传给 `n`。**不要自己数。**
- `· 空` = 这一节自己没正文（通常是个父标题），**别读它**，读它下面缩进更深的子节。
- `· 268 字` = 这一节自己的正文长度。很长的节读回来会被截断，响应里的 `note` 会告诉你续读的 `offset`。
- 导言不在 `toc` 里，它是 `n=0`。

## 读一节

```bash
# 按编号
curl -s {{AUTH}}\
  "{{BASE_URL}}/kb/{知识库}/entry/ops/runbook.md/section?n=3"

# 按标题（从 toc 里直接抄，不用数编号）
curl -s {{AUTH}}\
  "{{BASE_URL}}/kb/{知识库}/entry/ops/runbook.md/section?title=回滚"
```

成功时返回 `{ ok: true, sectionTitle, pathText, content, note? }`。

**`note` 一定要读**，它有三种含义：

| note 说的是 | 你该怎么做 |
|---|---|
| 「自身没有正文（那是父标题），这里给的是子节 X」 | 这就是你想要的内容，直接用 |
| 「这一块就是没有内容，**别在这一节上重试**」 | 别重试，换别的节或换别的条目 |
| 「本节共 N 字，这里给了前 M 字，继续读传 offset=M」 | 需要更多再续读一次，通常一次就够 |

## 查不到时（`ok: false`）

```json
{ "ok": false, "error": "《运维手册》里没有标题对得上「部署」。…",
  "candidates": [ { "section": 1, "sectionTitle": "上线流程", "chars": 1203 } ] }
```

**这不是错误，是提示**：`candidates` 就是这一页的真实章节清单，用它里面的编号再读一次。不要重试同一个标题。

## 不知道去哪找

```bash
curl -s {{AUTH}}\
  "{{BASE_URL}}/kb/{知识库}/manifest?budget=2000"
```

返回按预算裁剪的分层概览（目录 → 条目），用来决定「先看哪一块」。看到具体条目后再 `search` 或直接 `toc`：

```bash
curl -s {{AUTH}}\
  "{{BASE_URL}}/kb/{知识库}/entry/ops/runbook.md/toc"
```

## 连不上怎么办

**先把结论告诉用户，不要自己反复重试。**按下面四条对号入座，每条都说得出“接下来该谁做什么”。

| 你看到的 | 最可能的原因 | 告诉用户 |
|---|---|---|
| `curl: (7) Failed to connect`、拒绝连接、超时 | kb-lite 没在跑 | 打开桌面上的 KBLite（或在终端里跑 `kb-lite serve`）。启动后它会显示地址与端口 |
| 返回 HTML 页面、或 404 说没有这个接口 | 端口对不上，那个端口上是别的服务 | 看一下 kb-lite 界面上「运行中」后面那个地址，把端口改成它 |
| `401`、`unauthorized`、“缺少或错误的访问密码” | 服务开了访问密码，你手上没有或不对 | 向用户要那句“我的知识库服务在 ……，访问密码是 ……”，他说不出来就让他到设置页复制一次 |
| `503`、`paused`、“服务已经暂停” | 用户在界面里暂停了服务 | 让他在界面右上角点「启动」，恢复不需要重新整理 |

四条都对不上时，不要继续猜。把这几样原样告诉用户：请求的完整地址、HTTP 状态码、响应里的 `error.code`，
再说一句“看着不是我能自己修的”。

- 版本不对、想升级、或怀疑是程序本身的问题：https://github.com/summerset-zz/kb-lite/releases

## 不要做的事

- ❌ 不要 `?content=1` 拉整篇长文档塞进上下文（只在用户明确要求原文时用）。
- ❌ 不要为了「多试几次」重复调用 `search` —— 一次把多个说法放进 `q`。
- ❌ 不要修改任何文件。这个服务是只读的，没有写接口。
- ❌ 不要把 token 写进回答、日志或代码里。
- ❌ 不要在知识库里没有的内容上编造。知识库是**用户自己的资料**，不是通用知识；找不到就说找不到，并说明你搜了什么。

## 服务端渲染时填什么

| 占位符 | 内容 |
|---|---|
| `{{BASE_URL}}` | `http://127.0.0.1:<实际端口>` |
| `{{AUTH}}` | 命令里的鉴权头。读取密码开着时是 `-H "Authorization: Bearer <token>" `；关着时是**空串**（不能留一个空的 `Bearer `） |
| `{{AUTH_NOTE}}` | 鉴权说明那一行：“每个请求都要带 `-H …`”，或“这个服务没有启用访问密码，直接请求即可。” |

**没有“库列表”占位符了。** 它把库列表写进了会装到用户目录的那份文件，
用户加一个库它就过期。现在说明书只依赖“地址 + 密码”这两件真稳定的东西，
库认 agent 自己 `GET /kb` 取。

## 维护要求

- **测试锁**：CI 里断言本模板里出现的所有查询参数（`q`、`limit`、`n`、`title`、`offset`、`budget`）都在路由定义中存在，且 `note` 的三种文案与 `notes.go` 里的常量逐字相同。
- 当接口变化时，先改 `notes.go` / 路由，再改本模板 —— 顺序反了就会出现「文档说要传的参数并不存在」。
