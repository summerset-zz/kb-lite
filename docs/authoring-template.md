# 把文档整理成 kb-lite 的 markdown

目标不是「转成好看的 markdown」，而是「转成**能被搜索命中、能被按节读取**的 markdown」。

下游是一个只读的检索服务：它按**标题行**把文件切成若干节，按**关键词 × 出现位置**打分，
然后把「标题 + 摘要 + 章节目录（每节还带字数）」交给另一个 AI。它**不会**把整篇正文一次性塞过去，
所以「结构」比「文采」重要得多。

服务地址：`{{BASE_URL}}`
鉴权：{{AUTH_NOTE}}

## 一、文件头（frontmatter）

每个文件**必须以**这一段开头 —— 第一行就是 `---`，而且必须闭合：

---
title: 上线与回滚
summary: 每次发布的完整流程，以及出问题时怎么退回上一个版本。
tags: [部署, deploy, 回滚, rollback]
---

- `title`：会出现在搜索结果的第一行。**取人话名字**，别照抄文件名，也别写成「文档1」。
- `summary`：**一句话，200 字以内**。这是搜索结果的摘要。写具体内容，不要写「本文介绍了……」这种空话。
- `tags`：2–5 个。**它参与打分**，所以放用户真会拿去搜的词 —— 同义词、英文缩写、常见误写都放进来。
- 可选 `draft: true` 或 `kb_ignore: true`：这一篇不放进知识库。
- 只写上面这几个键。别的键会被忽略，但只会平白增加出错概率。

## 二、标题：整份文档最要紧的部分

切片器**只看标题行**。标题写错，这篇内容的可检索性基本就废了。

- 用 ATX 标题（`#` `##` `###`），**顶格写**，`#` 后面必须有空格。
  **不要**用「标题 + 下面一行 `====`」的下划线写法 —— 我们不认，它会变成普通正文。
- 从 `#` 开始，最多到 `######`。不要为了好看跳级。
- **同一篇里标题不要重名。** 出现两个 `## 常见问题` 时，按标题定位会失败：
  系统不会替你挑一个，而是把整页的章节目录退回来让人重选。给能区分的名字。
- **每节正文控制在 1500 字以内。** 超过的部分在读取时会被截断，调用方还得再请求一次才看得全。
- 标题里不要放 emoji 或装饰前缀（`## 🔧 配置`）—— 标题是给人扫目录用的，前缀只会干扰匹配，
  真要分类就用 frontmatter 的 `tags`。
- 代码块里可以有 `#`，但**围栏必须闭合**。没闭合会把后面所有标题都吞进代码块里。

## 三、正文

- **一篇文件只讲一件事。** 不要把一整本书 / 一整份手册塞进一个文件：
  它切出来的目录会有几百行，调用方完全找不到重点。按大章节拆成多个文件，用相对链接互相指向。
- **删掉原文档自带的章节编号**（「第一章」「1.2.3」）。编号由系统自动生成，而且是全局扁平的
  （`0,1,2,3…`）。原编号留着，目录就会变成 `1.2.3 1.2.3 配置` 这种。
- **删掉目录页、封面、页眉、页脚、页码、版权页。** 它们会被当成正文：既污染搜索，又白占预算。
- 开头**不要**放一大块「信息框」式的键值表格（人物卡、参数卡那种）。
  摘要会自动跳过开头的表格，所以它对摘要毫无贡献，还白占正文长度。
  确实需要的话，放到第一个 `##` 标题之后。
- 表格保留（GFM 表格）。图片**不要贴 base64**，只留一句有意义的 `![说明](图.路径)`，
  或者干脆写成文字描述 —— 检索层不读图，只有 alt 文字和正文有用。
- 引用角标 `[^1]` 在摘要里会被自动清掉，正文里保留即可，不用特意处理。
- 链接指向知识库里别的文件时用**相对路径**（`../ops/runbook.md`）；外部链接正常写。
- 全部 UTF-8、换行 LF。留意 Word 带出来的软回车和不间断空格，转完检查一下。

## 四、文件名与目录

- 文件名是「这篇没有标题时」的兜底标题，所以要**有意义**：`deploy-runbook.md`，不要 `文档1.md`。
- 不要用 `README.md` / `index.md` / `Untitled.md` 当正文文件名 —— 这类名字信息量为零，
  系统会改用父目录名（`docs/api/README.md` 会变成「api」）。
- 目录名也参与打分。放进 `ops/`、`guides/` 这种目录本身就是一种分类，不用在标题里重复写。

**写到哪个目录**：先问用户要放进哪个知识库，再取一次列表：

```bash
curl -s {{AUTH}}"{{BASE_URL}}/kb"
```

返回里每项都有 `name` 和 `rootPath`。`rootPath` 就是这个知识库在磁盘上的实际位置，
把整理好的文件写进去。

- 名字对不上时（用户说的和列表里的不一致），把列表列给用户让他选，**不要猜一个相近的**。
- **在 `rootPath` 下面新建一个子目录再写**（用来源文件夹的名字），不要平铺到根目录：
  根目录里可能已经有用户自己的文件，混在一起以后谁也分不清哪篇是转的。
- **不覆盖已有文件。** 同名就先问一句，或者加后缀（`-2`），不要悄悄盖掉。
- 写完告诉用户在 kb-lite 界面里点一次「更新」，新文件才会被收录 —— 它不会自己扫目录。
- 用户还没建知识库时，让他先去界面里加一个，**不要自己挑一个目录**往里写。
- 不要在 `rootPath` 里建 `.git`、`node_modules`、`.obsidian` 这类目录：它们会被跳过。

## 五、从具体格式转换时要注意的

**先认一下工具。** 下面只是常见几种。老的二进制 `.doc`、Apple 的 `.pages` / `.key`、
加密 PDF、扫描件，你手上的工具不一定处理得了。遇到就**直说做不到**，并告诉用户怎么办
（在原程序里另存为 docx/pdf、先 OCR），**不要硬转，也不要假装转成了**。

**Word（docx）**
- 「标题 1 / 2 / 3」样式 → `#` / `##` / `###`；正文样式 → 普通段落。
- 自动编号的列表保留成 markdown 列表；手打的「一、（一）1.」改成普通列表，或者直接删掉编号。
- 批注、修订痕迹、脚注区的分隔线，一律丢弃。

**PDF**
- **跨页被切断的段落要合并回一段** —— 这是 PDF 转换最常见的破坏。
- 每页底部的页码、页眉里的文档名，删掉。
- 分栏排版经常被打乱阅读顺序，转换后**通读一遍**再决定标题层级，不要照着文本流硬切。
- 扫描件没有文字层时不要硬转 —— 直接告诉用户这份需要先 OCR。

**网页**
- 只留正文（`<main>` / 文章主体）。导航栏、侧边栏、评论区、分享按钮全删。
- 不要保留原始 HTML 标签。正文必须是 markdown。

## 六、一次处理一批文件

用户说「把这个目录里的 doc 都放进知识库」时，按这个顺序做。**不要一边看一边就开始写。**

1. **先看清单。** 列出源目录里的文件，按扩展名分组，报给用户：
   「能转的 12 个（.docx 8、.pdf 3、.md 1）；我转不了的 2 个（.doc 1、.pages 1）」。
   数字要对得上，不要“大约”。
2. **把转不了的怎么办说清楚。** 让用户在原程序里另存成 docx/pdf，或者告诉你用别的办法。
   跳过不说，用户会以为全都进去了。
3. **确认写到哪。** 用 `GET /kb` 拿到 `rootPath`，在它下面**新建一个子目录**（用来源文件夹的名字）。
4. **一批一批写，写之前确认。** 几百个文件时先写两三篇给用户看一眼，合适再接着写。
5. **最后报账。**写了几个、放在哪个子目录、**哪些被跳过以及为什么**，再提醒一句去界面点「更新」。

## 七、交稿前自检

逐条确认，任何一条不满足就改：

- [ ] 第一行是 `---`，frontmatter 闭合，`title` / `summary` / `tags` 都在
- [ ] 每个标题都顶格、是 ATX、`#` 后面有空格；没有 `====` 式标题
- [ ] 同一篇里没有重名标题
- [ ] 没有超过 1500 字的节
- [ ] 所有代码围栏都闭合了
- [ ] 没有目录页 / 页码 / 页眉页脚 / 封面
- [ ] 没有保留原文档自带的章节编号
- [ ] 一篇文件只讲一件事；太长已经拆开
- [ ] UTF-8 编码、LF 换行

## 不要做的事

- ❌ 不要为了「更好看」改结构（加引用块、加分割线、加表情符号标题）—— 这些不提升可检索性。
- ❌ 不要编造 `summary`。它会被当成这篇的内容介绍给下游，编造等于投毒。
- ❌ 不要输出 `.docx` / `.pdf` / `.html`。只要 markdown。
- ❌ 不要动用户已有的其它文件 —— 你只负责产出新的 `.md`。

## 这些规则是哪来的（改之前先看这里）

每条规则都对应一条**实现**；不是风格偏好：

| 规则 | 落在哪里 | 违反了会怎样 |
|---|---|---|
| frontmatter 必须第一行 `---` 且闭合 | [02](./02-slicing.md) Frontmatter | 整段被当正文；`tags` 不参与打分，`summary` 也不生效 |
| `summary` ≤ 200 字、写具体内容 | 02 摘要 / [04](./04-http-api.md) `search` | 摘要膨胀会直接撑大每一次 `search` 的回包 |
| `tags` 放用户真会搜的词 | [03](./03-search.md) 字段表（`body` 档） | 少一档命中，这条在排序里会整体掉下去 |
| 标题必须顶格 ATX | 02 分节算法第 2 步 | 缩进的或下划线式的「标题」是正文 → 整篇塌成一个大节，目录只有一行 |
| 同一篇标题不重名 | 04 `?title=` 定位 | 命中多节时返回 `200 + ok:false`，调用方得再读一次 |
| 每节 ≤ 1500 字 | 02 超长节 / 04 `offset` `maxChars` | 读取被截断，多花一次工具调用 |
| 代码围栏必须闭合 | 02 第 1 步（围栏状态机） | 后面所有标题被吞，等于后半篇从目录里消失 |
| 删掉原章节编号 | 02 编号规则（全局扁平，ADR-009） | 目录行变成 `1.2.3 1.2.3 配置`，编号空间被噪声占满 |
| 开头不要放信息框表格 | 02 摘要（`dropLeadingTable`） | 摘要取不到东西 → 搜索结果里那行摘要是空的 |
| 文件名要有意义 | 02 标题取值链 + `LOW_INFORMATION_STEMS` | 标题变成「README」「index」 |
| 一篇一件事 | 04 `toc` 文本格式 | toc 几百行，候选窗口里全是它自己 |
| 图片不贴 base64 | 02 `body` 前 20000 字符 | 一张图吃掉整个全文档的预算 |

## 维护要求

- 改 02 / 03 / 04 里的**字段名、字数上限、三种 note 文案**时，必须同步本文件 ——
  和 [`skill-template.md`](./skill-template.md) 的「同源」要求一样。
- 将来 daemon 提供 `GET /authoring.md`（v0.3 向导完成页的「复制整理说明」按钮）时，
  **必须从同一份常量渲染**，不许手写第二份。
- 本文件的措辞面向「一个正在帮用户整理文档的通用 AI」，不是面向实现者 ——
  加规则时先问「一个不懂 kb-lite 的模型看得懂吗」。
