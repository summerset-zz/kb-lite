# 维护 kb-lite 的知识库

你只做三件事：**加一个知识库**、**删一个知识库**、**给知识库改名**。

不查资料（那是 `kbl-query` 那一份），不写内容文件（那是 `kbl-authoring` 那一份），也不改知识库目录里的任何文件。

## 先确认你有手

**你必须能执行 shell 命令**。做不到就直接告诉用户：这一步要在他自己的电脑上跑命令，把命令给他，让他自己执行。**不要假装做完了。**

## 用哪个 kb-lite

**`kb-lite` 不在 PATH 里**，直接敲 `kb-lite` 只会得到“找不到命令”。下面所有命令都用这个完整路径：

```text
"{{KB_EXE}}"
```

- 路径里有空格或中文，所以**必须带双引号**，上面已经带了。
- 这台机器上可能还有别的 kb-lite（比如下载目录里忘了删的旧版本）。**只用这一个**：
  它是界面背后正在跑的那份，版本能对上；旧的可能连 `list --json` 都不支持。
- 万一这个路径不存在（用户挪了程序），停下来告诉用户，**不要自己换一个 exe 去跑**。

## 四条硬规则

1. **只用上面那个完整路径的命令行。** 不要用 `curl` 调 `/api/*`：那些接口要一把只存在本机的凭据，你拿不到，调了只会 401。
2. **删和改名之前必须让用户确认。** 把库的名字和它对应的目录一起说出来，等他点头。
3. **`remove` 只删登记与索引，绝不动目录里的文件。** 回话时一定要说这一句，否则用户会以为资料没了。
4. **名字先推测，但推完要问。** 命名规则：1 到 64 个字，不能含 `/` 和 `\`，不能是 `.` 或 `..`，不能与现有库重名。

## 一、加一个知识库

用户给的通常是一个目录，例如 `D:\kblite-libs\fontcover-docs`。

1. **看服务在不在**：`"{{KB_EXE}}" status`。退出码 4 表示服务没在跑。
   没有服务也能加（`add` 会直接改配置文件），但要告诉用户：服务起来之后才会开始整理。
2. **确认目录存在，里面确实有东西**：Windows 用 `dir "<目录>"`，macOS / Linux 用 `ls "<目录>"`。
   看有没有 `.md`、`.markdown`、`.txt`。目录不存在就停下来问用户，**不要自己建一个**。
3. **起名字**：从目录内容推测（README 第一行、frontmatter 里的 `title`、最常见的子目录名）。
   然后问用户用不用这个名字。动手前跑一次 `"{{KB_EXE}}" list --json` 看有没有重名。
4. **执行**：`"{{KB_EXE}}" add "<目录>" --name "<名字>"`
5. **回话**：加好了、会开始整理、进度在界面里看（或 `"{{KB_EXE}}" status`）。

## 二、删一个知识库

1. **先看清单**：`"{{KB_EXE}}" list --json`。确认用户说的名字确实在里面，把它的 `rootPath` 一起报出来。
   名字对不上（用户说的是目录名、是路径、或者记错了）就停下来问，**不要猜一个最像的**。
   如果清单是空的但用户说界面里明明有库：别自己建一个，先问用户
   （可能是他的 shell 里少了 `KB_LITE_CONFIG_DIR`，配置目录被改到别处了）。
2. **问确认**，把这两句说清：
   - 要移除的是「名字」，它对应「目录」。
   - 只会删掉 kb-lite 自己的登记和整理结果，那个目录里的文件一个都不会动。
3. **用户同意之后**才执行：`"{{KB_EXE}}" remove "<名字>" --yes`
   `--yes` 只能在用户明确同意之后加。不加会卡在交互确认上，没问过就加等于替用户做决定。
4. **回话**里必须带那句“文件没动”。

## 三、给知识库改名

1. `"{{KB_EXE}}" list --json` 确认旧名字存在。
2. 按上面第 4 条硬规则校验新名字，并确认不与现有库重名。
3. 问确认。顺带说清代价：**地址里那一段会变**，别的不受影响，文件不动、不用重新整理、装好的 SKILL 也不用重装（说明书里不写库列表）。
4. 执行：`"{{KB_EXE}}" rename "<旧名>" "<新名>"`
5. **改完重新拉一次清单**（`"{{KB_EXE}}" list`）。旧名字拼出来的地址全部失效，`/kb/旧名/...` 会回“没有这个知识库”。

## 出错时

| 你看到的 | 怎么办 |
|---|---|
| 退出码 4 | 服务没在跑。`remove` 与 `rename` 需要它；`add` 不需要（会直接改配置，下次启动生效） |
| 名字不合法 / 重名 | 把原文给用户看，**不要**自己换个名字再试一遍 |
| 目录不存在 | 停下来问用户，不要替他建目录 |
| 清单是空的 | 先问用户。别自己建库，也别去改环境变量 |
| 401 | 你用了 `curl` 打管理接口。改成上面那个完整路径的命令 |
