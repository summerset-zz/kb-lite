# 06 · 界面：Web UI 与纯 Go 托盘

> **一个 Go 二进制**。UI 是 `//go:embed` 进去的静态资源，用系统浏览器打开。Windows 上同一个进程再挂一个托盘图标。
> 不上 Tauri 或 Electron，理由见第一节与 ADR-014。
>
> 本文合并了 `GUI-DESIGN.md` 的设计稿，并补齐了原稿没覆盖的规格。实现以本文为准。
> **UI 能做的事，CLI 必须也能做**（`docs/05`）。UI 只是 `/api/*` 的一个客户端，不许有自己的业务逻辑。
> 行文与文案遵循 `docs/11-writing-style.md` 与本文第八节。

## 一、为什么不上 Tauri

| | 浏览器 UI（采用） | Tauri 壳 | Electron |
|---|---|---|---|
| 用户要装什么 | 不需要 | 安装包 + WebView 运行时 | 安装包，自带 Chromium，约 150 MB |
| 包体 | 约 11 MB | 约 11 MB + sidecar 11 MB | 约 150 MB |
| 一台机器出全部平台产物 | 可以 | **不行**，不能从 Windows 交叉编译出 macOS | 可以 |
| 托盘 | 纯 Go 自己实现（Windows） | 有 | 有 |
| 签名 | 不需要 | Windows 证书与 macOS 公证都要钱 | 同左 |

三条否决理由，任一条单独成立就够了。

1. **交叉编译断了**。`docs/08` 里“一台 Windows 出五个平台的二进制”是换 Go 换来的最大收益。Tauri 要 Rust 工具链，且必须每平台各自构建。
2. **签名**。未签名的 Tauri 包在 Windows 被 SmartScreen 拦，在 macOS 被 Gatekeeper 拒。本项目不收钱，这笔开销没人出。
3. **它换来的只是托盘**。Windows 上 `Shell_NotifyIcon` 纯 `syscall` 就能做，不需要 cgo，也不影响交叉编译。

macOS 与 Linux 的托盘需求若真的出现（`docs/09` 的 v2 条件），再评估 Tauri。那时也要先把签名预算定下来。

## 二、进程形态

一个进程（`kb-lite serve`）同时做四件事：扫描切片、HTTP 服务、托管 UI、托盘（Windows）。没有 sidecar，没有第二个进程。

```
kb-lite serve            # 前台进程：监听、索引、托盘（Windows 上自动挂）
kb-lite serve --open     # 额外打开默认浏览器到 UI
```

**双击 exe 等同于 `serve --open`**（`docs/05`）。双击是普通用户的第一个动作，
让它打印一段用法就退出等于没反应：窗口一闪而过，他连报什么都看不到。
想知道用法的人会敲 `--help`，不会靠双击。

**双击启动时把那个控制台窗口收掉**（Windows）。系统会给控制台程序开一个黑窗口，
而关掉它等于杀掉进程：用户多半会顺手关掉，然后发现服务没了、AI 也连不上，却没有任何提示。
收掉之前先确认这个控制台是**我们自己一个人的**（`GetConsoleProcessList` 只有一个进程），
从 cmd / PowerShell / Windows Terminal 里跑的就不动，那是用户的窗口，收掉连 Ctrl+C 都没了。
没有控制台之后删掉 stdout/stderr 的去处一律指向 devnull。
代价：这条路没有 Ctrl+C 了，停服务只能走托盘菜单或界面里的“退出 kb-lite”。

- **关闭浏览器标签不等于退出**。daemon 还在跑，托盘图标还在。UI 里要有一行小字说明，并给“退出 kb-lite”按钮。
- **暂停服务与退出是两个动作**，托盘、UI、CLI 三处叫法必须一致：
  - 暂停服务：**只关掉给 AI 用的那一面**（`/kb/*`、`/skill.md` 返回 `503 paused`）。进程、索引、托盘、界面都保留。
    监听不关，否则界面里那个「继续使用」按钮没人送得到，`kb-lite start` 也没有可以唤醒它的通道。
    再点启动立刻恢复，不重新整理。对应 `kb-lite stop`。
  - 退出：关监听，关记录文件，进程结束。对应 `kb-lite quit`。
- **单实例**：`<配置目录>/lock` 里写 pid、实际端口、启动时间与 exe 路径。重复双击或重复 `serve` 时，
  先看 pid 是否还活着、再看那条端口上是否真有人应答，两者任一成立就把 UI 打开并退出自己。
  **不这么做的话第二个进程会默默占下一个端口**（端口自动 +1 让不冲突变成默认），
  托盘里出现两个图标、配置被反复改写。热重开改端口后锁也要跟着改。
- 端口被占自动加一，实际端口写回 `config.json`。UI 一律从 `/api/status` 读地址，不硬编码。

## 三、技术栈（ADR-016）

| 项 | 选择 | 约束 |
|---|---|---|
| 构建 | Vite + Vue 3 + TypeScript | 产物 `web/dist` 拷到 `internal/daemon/static/`，再 `//go:embed`。用户侧永远不需要 Node |
| 样式 | Tailwind CSS v4 | 设计 token 与组件级样式写在 `web/src/styles.css`，不引 CSS-in-JS |
| 交互原语 | 原生 `<dialog>`（v0.3） | 只买焦点陷阱、Esc 关闭、无障碍；这三件浏览器已经做对了，所以**先不引 Reka UI**。等真需要弹层锚点定位再引，别为两个弹窗拖进一整套组件库 |
| 图标 | 内联 lucide 路径（`web/src/components/AppIcon.vue`） | 为几个图标引一套按需打包配置不划算。要加图标就在那个文件里加，别在组件里各画一遍 SVG |
| 禁止 | SSR、Nuxt、Element Plus、Naive UI、Ant Design | 这不是后台管理系统，也不要为一个本地工具拖进整套组件生态 |

硬规则：

- 禁止用 `innerHTML` 渲染任何来自知识库或用户输入的内容。markdown 预览走消毒过的渲染器，禁用原始 HTML。
- 字符串集中在 `strings.ts`。先只做中文，不散落在组件里。
- 网络调用收敛到 `api.ts` 一层，组件里不出现裸 `fetch`。

**控件记法**：本文件里的 `[按钮文本|↓]` 表示一个**分体按钮**：左半边是动作，右半边只开下拉菜单。
实现在 `web/src/components/SplitButton.vue`。

- 右半边用 `chevron-down` 图标，**不要写成文字竖三角**。
- 左半边单独可点；`menuOnly` 那种变体（写成 `[操作|↓]`）左半边也只开菜单，因为它没有默认动作。
- 两半边共用一条边框（往左压 1px），颜色随 `primary` 一起变。
- 为什么要分：一行里只放一个「操作」按钮，用户不知道点下去是执行还是展开；
  放两个按钮又占地方、还容易点错。

## 四、托盘（Windows）
图标只有两态：**服务在跑**、**服务已暂停**。不做“处理中”的第三态。Windows 上频繁重绘托盘图标观感很差，动画帧更糟。进度属于窗口内的信息（放在 tooltip 与菜单那一行里）。

两态用两张源图（`internal/tray/assets/normal.png` 与 `warn.png`，512×512 透明底），运行时按系统 `SM_CXSMICON` 缩放。换图与生成链路见 `docs/08` 的「图标」一节。
**不要**把它们预先切成 16×16 塞进仓库：高 DPI 屏要 24/32，切死了就糊。

右键菜单，自上而下：

```
已在 http://127.0.0.1:7331 运行          ← 可点的普通项：点击复制地址并弹气泡
──────────────────────────────────
暂停服务 / 启动服务
正在索引 120 / 530                       ← 仅索引进中时出现，点击打开 UI
设置                                     ← 打开浏览器到 /#settings
在命令行中打开                            ← 打开终端到程序所在目录并跑一次 kb-lite -h
──────────────────────────────────
退出
```

约束：

- 不做灰掉的 disable 项。地址那一条可点复制，索引进度那一条可点打开界面。
- 双击托盘打开 UI。UI 的默认首页就是知识库页，设置是它里面的一页。页签跟着 URL 锚点走
  （`/#settings`、`/#about`），所以托盘可以直接把用户送到设置页。
- 不弹系统通知，“已复制”这类一秒气泡除外。整理完成不打扰用户。
- 菜单每次右键**现建**：内容永远等于此刻的状态，不需要缓存或监听。
- 实现要点（`internal/tray`）：隐藏窗口加消息循环，调 `user32` 与 `shell32`，不加 cgo。
  图标在内存里生成（16×16 圆点，`CreateIconFromResourceEx` 吃一块手搓的 `ICONIMAGE`），
  **不引入任何图片资源**。平台代码放 `_windows.go`，其他平台编空实现。
- 托盘起不来不影响服务：打一行提示就继续跑，用户还能用浏览器打开界面。
  `serve --no-tray` 给服务器与脚本用。
- macOS 与 Linux 暂不提供托盘，用 `kb-lite autostart enable` 加 `serve --open` 覆盖“开机就要能用”。

## 五、页面

### 5.1 首次启动向导（只出现一次）

判定条件：`config.json` 不存在，或 `setupCompleted` 为 false。之后可以在设置页重新运行向导。

向导是四屏：欢迎（东西放在哪）、端口与接口公开范围、创建知识库、总结。前三屏里只有第二屏真的改东西，其余是“读一眼、点下一步”。目标用户第一次打开时最需要知道的是“它把我东西放哪了”和“别人能不能看到”，不是被要求做一串技术决定。

**第 1 屏 · 欢迎 + 东西放在哪儿（只告知，不给选）**

```
欢迎使用 KBLite v0.3.0
这个向导会带你做完三项设置。以后随时可以重新运行它。

你的配置文件和索引都存放在这个位置：
  C:\Users\me\AppData\Roaming\kb-lite        [复制]
这个目录只有当前用户（me）能访问。备份的时候把它整个复制走就行。
```

- 用户名取 `USERNAME` / `USER` / `LOGNAME`，都没有就用家目录名。它只是一个**给人看的称呼**，
  不要为它引 `os/user`（部分平台上要么要 cgo，要么要读 `/etc/passwd`）。
- 路径用 `<pre>` 展示（可选中、可横向滚动），复制按钮带图标，复制后图标变成对勾。
- 回答“东西会不会丢”：这句只说明它属于谁、怎么备份，不再额外解释缓存是什么。

**不要给用户选缓存文件的位置。** 一个为了“这个文件放哪”的输入框，对目标用户是纯噪音，
还会造出“config 指向 A、缓存落在 B”的畸形部署（ADR-018）。要换地方就是换配置目录、整包搬家。

“这台设备共用还是这个用户专用”这个选择也暂时不做：配置目录在**进程启动时**就定了，
UI 里改它必须先写一个指针再重启进程，向导会变成“做一件事 → 重启 → 再做两件”；
而且设备级要写 `C:\ProgramData`，创建出来的子目录默认只有创建者能写，得显式改 ACL。
真要做的时候一次做全（指针文件 + ACL + 重启提示），不要半截。

**第 2 屏 · 端口与接口公开范围**

```
端口  [7331]
     默认为 7331，如果被占用会自动换一个。

接口公开范围
  ● 仅本设备       推荐：在本设备用 http://127.0.0.1:7331 或 http://localhost:7331 访问。
  ○ 共享到局域网    局域网里的其他设备可以用 http://192.168.1.5:7331 访问。
```

选了「共享到局域网」才出现的黄条，两句话照抄：

> 如果你连着 VPN，或者用了 Tailscale 这类工具，那个网络里的设备同样能访问。
> 为了安全，会自动生成一个访问密码。它只影响给 AI 用的接口，不影响你打开这个界面。

- **VPN 那句是真的**：绑 `0.0.0.0` 会监听所有网卡，包括 VPN 的虚拟网卡，所以能路由到本机的 VPN 对端也能访问。防火墙可能挡住，但不要拿它当安全边界。
- 局域网地址由服务端从网卡上读（`/api/status` 的 `lanAddrs`，只取 IPv4 且跳过回环与链路本地）。拿不到就写“这台机器的局域网地址”，**不要编一个 IP**。
- 「访问密码不影响本界面」这句必须留着：否则用户会以为开了密码之后连自己都进不去。

**第 3 屏 · 创建知识库**

```
KBLite 的数据源是你设备上的一个文件夹。我们会把那个文件夹里的 markdown 文件录进知识库。
如果你平时用别的工具写文档，最后一步还有一个“让 AI 把文档整理成 markdown”的 skill。

当前已有以下知识库：
  字体内容   D:\git repo\fontcover-workspace\fontcover-content
  项目文档   D:\git repo\fontcover-workspace\fontcover-v2\docs

[添加目录]
```

- 重新运行向导时，**先把已有的库列出来**。用户点“重新运行向导”通常只想改端口或密码，看到空白会以为之前加的库没了。
- 没有库时给一条黄条：还没有知识库，先添加一个再继续。但**不拦着**往下走，否则一个目录都加不上的人会卡死在这一屏。

**添加目录的弹窗**

- 标题：选择知识库目录。
- 主提示：这个目录下的所有 md 文件都会当成知识库的数据源。第一次用可以先建一个空目录；也可以直接把文件夹路径粘到上面。
- 列表：盘符和普通目录**用同一种行样式渲染**，只是图标不同（盘符用硬盘图标，目录用文件夹图标）。盘符不是页面上另一排按钮，对用户来说它们就是“上一层里的文件夹”。
- 名字：标签“知识库名称”，说明是“AI 能看到这个名称，并按你的描述查对应条目”。默认取文件夹最后一段，盘符根退回“新的知识库”。
- 底部只有一组按钮：取消 / 添加。

**点“添加”之后先探一次再确认**（`GET /api/fs/probe`）：

| 情况 | 追问 |
|---|---|
| 磁盘根目录 | 这个位置是磁盘根目录，整块磁盘上的 markdown 文件都会进知识库。确定要添加吗？ |
| 有 N 篇 markdown | 这个目录下已经有 N 个 markdown 文件，确认要添加吗？ |
| 一篇都没有 | 这个目录里还没有 markdown 文件。以后往里放就行，确认要添加吗？ |

- 磁盘根**不数文件**：走一遍整盘要几分钟，而这种情况走的是另一套问法，根本不需要数字。这一条很重要，早先的实现会在这里卡住好几秒。
- 普通目录数一次，封顶 2000 篇，到顶就说“2000 个以上”。
- 数文件只在用户点“添加”时发生一次，**不在列目录时数**（那样每换一层都要走整棵子树）。

**第 4 屏 · 总结**

```
配置完成
你的知识库已经准备好了。以后可以重新运行这个向导，也可以在设置里单独改某一项。

配置文件位置   C:\Users\me\AppData\Roaming\kb-lite
网络           仅本设备：在本设备用 http://127.0.0.1:7331 访问知识库。
               （共享到局域网时再列一行访问密码，用 <pre> 展示）

知识库
  字体内容   D:\…\fontcover-content
  （没有库时：还没有添加知识库，你可以稍后自己添加。）

给 AI 用的说明书
  装好之后要重启一次 AI 工具才生效，它只在启动时读那个目录。懒得重启，就把下面那段话直接贴给它。
  [安装检索 SKILL] [安装整理 SKILL]
```

**SKILL 不自动安装。** 写进用户 home 下的目录必须是显式动作（ADR-004：我们连写文件的能力都刻意没有），而且见下面那条“不做响应式”的说明：自动装完看起来完成了，实际不重启不生效，用户会以为坏了。所以这一屏给两个按钮，和知识库页的「让 AI 用起来」是同一个组件。

四个“给 AI 用的东西”保留，但收进一个默认折叠的 `<details>` 里（“给 AI 用的东西（现在不想看就收起）”）：用户此刻的注意力在“配好了没有”，不是接口示例。每段**先把内容摊开**（`<pre>`，长文本只露前 10 行并注明“点复制拿到全文”），再配一个复制按钮：

| 标题 | 内容 | 次要说明 |
|---|---|---|
| 给 AI 的说明书 | `/skill.md` 的全文 | 放在 AI 工具认识的目录里，它就会用这个知识库 |
| 说明书地址 | 一行 URL（`{{BASE_URL}}/skill.md`） | 工具里若有“填一个网址当资料源”这种入口就填它；要密码的工具填不了，就粘上面那一段 |
| 整理说明 | 写作 skill（`/authoring.md`）的全文 | 交给另一个 AI，让它把 docx、pdf 这些整理成能进知识库的格式 |
| 命令示例 | 一条可直接粘贴执行的命令，按当前访问密码设置决定是否带 `Authorization` | 想自己试试接口时用 |

**这一页不要放“MCP 配置”。** 那个地址返的是 markdown，不是 MCP 服务端点，
任何 MCP 客户端连上来都会握手失败。MCP 将来只做“把调用转发到本地 HTTP”的薄壳（ADR-006），
做完再把这一块换成真配置：`{"command":"kb-lite","args":["mcp"]}`。现在放一个很像是配置的东西比不放更糟。

文字块上方统一加一行（§8.5 的原文）：这一段是给 AI 用的，你不用看懂。点“复制”把它粘给 AI 就行。

**关于 SKILL 的加载方式**：主流 harness 都在会话启动时扫一遍 skill 目录，**没有响应式监听**。所以我们装完只能提醒“重启一次 AI 工具”，并且给一段可以直接贴进对话的话作为绕路。任何承诺“装完立刻生效”的文案都是错的。

第 3 屏是产品的最后一公里。用户卡住的从来不是接口设计，而是怎么接进自己的 AI。

### 5.2 知识库页（默认首页）

列表每行（两行文字 + 行尾动作）：

```
[√] 字体内容  已就绪 8 分钟前更新                        [操作|↓]
128 篇文档 | 743 个章节 | 2.1 MB
```

- 行首图标是语义的，不是装饰：`√`（`check`，主色）表示这次收录完整，
  `!`（`alert-circle`，警示色）表示有文件没进去或这次没整理成，
  时钟（`clock`）表示正在整理。
- 状态文字按顺序取第一条成立的：正在整理 / 这次没整理成 / 已关闭 /
  `<N> 篇文档未成功入库` / `已就绪 <时间>更新`。
  有文件没进库时**不要**再写“已就绪”：AI 确实查不到那几篇，说就绪等于骗人。
- 第二行只放三个数字：篇文档、个章节、占用大小，中间用 `|` 隔开。
- **根目录路径不铺在行上**。它在行尾那个下拉里，按需复制或打开。

操作（`[操作|↓]`，自上而下）：

| 操作 | 说明 |
|---|---|
| 更新 | 增量整理。只重切 sha1 变过的文件（`reindex` 不带 force） |
| 全部更新 | 全量重切（`force: true`） |
| 查看入库日志 | 弹窗：这次收录了多少、哪些文件没进去、为什么（见下） |
| 打开文件位置 | 用系统文件管理器打开根目录。只开窗口、不写文件（`POST /api/fs/reveal`） |
| 复制路径 | 把根目录路径放进剪贴板 |
| 启用或禁用 | 关掉后这个知识库的 `/kb/…` 全部返回 `503 kb_disabled`。文件与索引都不动，重新开启不需要重新整理 |
| 改名 | 名字可以改，内部 `id` 不变，不需要重建索引 |
| 移除 | 二次确认。必须写明不会删除 `D:\notes` 里的任何文件，确认按钮写“移除”而不是“确定” |

**入库日志弹窗**（`GET /api/kbs/{name}/report`）：

```
这次收录了 128 篇文档、743 个章节。
有 2 个文件没有进知识库：
  drafts/草稿.md：文件开头写着要跳过（draft 或 kb_ignore）
  bad.md：编码认不出来，没有收录
另有 1 条提醒。这些文件已经收录了，只是内容里有点问题：
  ops/runbook.md: frontmatter 不是合法 YAML，已按行宽松解析
```

- 服务端两张名单各封顶 100 条，超出时末尾写“只列出前 100 条”。总数看 `skippedTotal` 与 `warningTotal`。
- 建了但还没整理过的库也回 `200`（空报告），弹窗里说“还没整理过”。不要回 404：
  那一行的按钮照样能点，收到错误码只会让人以为坏了。
- “没进知识库”与“已收录但有提醒”必须分开列。混在一起时用户会以为少了文件，
  而实际上只是写法不规范（frontmatter 严格解析失败但正文救回来了）。

- **命名**：名称默认取路径最后一段。重名自动加序号，写成 `notes (2)`、`notes (3)`，对话框里可以改。校验沿用 `docs/04`：1 到 64 字，不含 `/`、`\` 与控制字符，且唯一。
- **目录选择器**走 `GET /api/fs/list`，由服务端列目录，不是系统对话框。列表只给目录名，
  **不再数里面有多少 markdown**：那是递归走整棵子树，在大盘根目录上换一层要等好几秒。
  想快就直接把路径粘进输入框（见下）。
- **选择器就是个完整的弹窗**（`<dialog>`），不是按钮下方就地展开的一块：屏幕小或者页面长的时候，
  它出现在视野外，用户看到的只是“点了没反应”。向导与添加知识库都用同一个组件。
- **确认在弹窗底部，紧挨“取消”**。以前“用这个文件夹”摆在右上角，与底部的关闭按钮隔着半个屏幕，
  用户分不清哪个才是“就选这个”。弹窗里**只留一组按钮**：取消 + 确认，不要再加一个重复的“关闭”。
- **名字也在弹窗里问**。名字属于“我正要创建的这个知识库”，留在页面上会让“选文件夹”与
  “真的建一个”变成两件看不出关系的事（用户会问：怎么确认创建？怎么再加一个？）。
  默认值取文件夹最后一段，盘符根（`D:\`）退回“新的知识库”。
- **右下角只有一个动作**：建好之后列表里就有它了，右下角那个按钮是“开始使用”（结束向导），
  不是“确认创建”。要再加一个就再点“添加一个知识库”，多少次都行。
- **“新建文件夹”**：选着选着发现目标文件夹还没建，就地建一个（空目录），建完直接进去。
  不要用户切到资源管理器建完再回来。
- **在用户目录里就说一句**：选中的位置落在当前用户的用户目录里时，弹窗里提醒
  “换一个电脑用户登录后，kb-lite 读不到它，索引也就更新不了；想多人共用就把资料放在 `D:\` 这类公共位置”。
  不说的话，用户换个人登录看到读不到目录，只会以为程序坏了。
- **弹窗要自己写 `margin: auto`**：Tailwind 的 preflight 给所有元素（含 `::backdrop`）加了 `margin: 0`，
  而 `<dialog>` 靠的是 UA 样式里的 `margin: auto` 居中。不写回来，弹框就贴在左上角。
- **盘符根目录上“返回”要能退回盘符列表**：`D:\` 没有上一层，但还有“选哪个磁盘”那一屏。
  只看 `parent` 的话，用户一进到 `D:\` 就再也退不出来了。
- **路径可以手动输入**：顶上那条就是输入框，点着能改、能把路径粘进来（从资源管理器的地址栏复制），
  回车或“前往”跳过去。列表只适合一层一层点，跳很远的时候逐层点没人受得了。
  跳失败时输入框保留用户打的字，别清回原位 —— 他要改的就是那一处。
- **手上还没有路径时给起点**：Windows 先列盘符（`C:\`、`D:\` …），其它平台从家目录开始。
  那时的提示写“先选一个磁盘，里面就是你的文件夹”，不要写“这个位置下面没有子文件夹”
  （当前位置压根还不存在，而“用这个文件夹”当时也点不了）。
- **换记录文件位置时，选中文件夹要拼回文件名**：这一项已经整个去掉了（ADR-018），
  保留这条只为了记住当时的坑：选中文件夹后直接把文件夹当文件路径写下去，重启后 SQLite 打不开它。

**SKILL 区块**：上下两组，检索与整理各一组，**不要合并**。

每组依次是：组标题、一句“它能干什么”、一行“怎么跟 AI 说”（原句显示 + 复制按钮）、
然后是**目标目录的现状**，动作就在那一行上：
```
检索 SKILL
让 AI 能查这个知识库：说明书里有地址、密码，也写清了“先搜再读、一次多个说法”的用法。
怎么跟 AI 说  用 kb-lite 去我的知识库里查一下……        [复制]

[√] 通用目录    3 分钟前更新                            [重新安装|↓]
[!] Claude Code  SKILL 未安装                           [安装|↓]
[!] 通用目录    SKILL 有更新                            [更新|↓]
```

- 行首图标与知识库一致：`√` 已是最新（主色），`!` 未安装（灰）或有更新（警示色）。
- 状态文字：`<时间>更新` / `SKILL 未安装` / `SKILL 有更新`。
- 按钮文字跟着状态走：重新安装 / 安装 / 更新。未安装与有更新用主色，重新安装用普通样式。
- **路径不在行上**。下拉里两项：复制路径、打开文件位置；没装过时只有复制路径
  （那个文件还不存在，打开它只会报错）。
- 状态从磁盘读（`GET /api/skill/status`），三态：未安装 / 已是最新（带时间）/ 有更新。
- 第三行是**不安装的用法**：“不想安装也可以，把这一段贴给 AI”，旁边也是复制按钮。
  那段话自带说明书地址（`<base>/skill.md` 或 `<base>/authoring.md`）；
  访问密码开着时把密码一并写进去，否则 AI 拿到 401 只会反复重试。
  界面里没有单独的“说明书地址”字段：地址已经在那句话里了，多一个输入框只会多一个歧义。
- **“有没有更新”比的是文件内容与此刻应该装的那份是否逐字相同**。地址、密码、说明书本身变一样就算过时。
  这就是以前“安装反馈和按钮不在同一个地方”的正解：反馈不是一句 toast，而是那一行现在的样子。
- 两个目标目录**互不兼容**：Claude Code 只读 `~/.claude/skills`，不读 `~/.agents/skills`。
  两者用的是同一套 SKILL.md 格式，所以要各装一份，而不是“装到通用目录、Claude 兼容”。

按钮下方两行小字，照抄：

> 服务地址或访问密码变了之后，这里会显示「有更新」；知识库增删改名不用管，说明书里不写库列表。
> Claude Code 会自己发现目录里的改动；如果那个目录是这次才建的，它可能要先运行 `/reload-skills`。
> 其他 AI 工具不一定，保险起见重开一次会话。

**关于“装完生不生效”**：Claude Code 官方文档写明了它会 watch `~/.claude/skills/`（会话中改 SKILL.md
不需要重启，`/reload-skills` 用于新建的顶层目录）；`~/.agents/skills` 这类通用目录没有这种保证。
所以文案分两层：Claude Code 说“它会自己发现”，其他工具说“重开一次”。**不要写“点一下立刻生效”**，
那对通用目录是做不到的。

```ts
// AI 工具那一侧大致是这个样子：启动时扫一遍，之后不再看磁盘。
// kb-lite 无法干预这一步，只能把文件放对位置。
const skillDirs = [join(homedir(), '.agents', 'skills'), join(homedir(), '.claude', 'skills')]
const skills = skillDirs.flatMap((dir) =>
  readdirSync(dir, { withFileTypes: true })
    .filter((d) => d.isDirectory())
    .map((d) => parseFrontmatter(readFileSync(join(dir, d.name, 'SKILL.md'), 'utf8')))
    .filter((sk) => sk.name && sk.description),
)
// 现在 skills 进了这次会话的上下文；工具不重启就不会再读第二遍
```

> [!NOTE]
> 两份 SKILL 必须分开装（ADR-017）。把写作规范塞进检索 SKILL 里，agent 会在只想查东西的时候也去改用户的文件。

**运行状态**：不放在知识库页，放在**顶栏**（左侧：运行中 / 局域网可用 / 已停止，带下拉的
启动、停止、复制地址；右侧：明暗切换）。全站状态藏在设置页深处时，用户根本不知道 AI 现在是连不上还是没在用。
知识库自己那点状态（ready / indexing / error / disabled 与整理进度）留在它那一行上。

页脚：`KBLite vX.Y.Z`、作者 [Summerset-zz](https://github.com/summerset-zz)、[反馈问题](https://github.com/summerset-zz/kb-lite/issues)、检查更新（v1 先占位）、支持作者。
最下面一行小字（全站都显示）：关闭配置页面不影响 kb-lite 运行。本配置界面可通过托盘区图标重新开启。
这句话以前只在设置页末尾，而最容易误以为“关掉页面就是关掉服务”的恰恰是知识库页的人。

### 5.3 搜索调试页

给用户回答两个问题：**为什么搜不到**，**为什么这条排第一**。这是用户自助排查的唯一入口（`docs/03` 的 `--explain` 是它背后那套数据）。

入口：导航第三个页签“检索测试”。没有知识库时整页只有一句“先添加一个知识库”。

> 名字是“检索测试”不是“搜索”：这一页是给用户排查“为什么搜不到、为什么这条排第一”的，
> 不是给人日常检索用的。叫“搜索”会让人以为它是主功能，而主功能是“让 AI 查”。

版面自上而下：

```
知识库 [字体内容 ▾]   查询 [____________] [搜索]
多词想同时查就都打进去，空格分开。
```

结果每条：

```
运维手册                                        12 分
ops/runbook.md · rev a1b2c3d4 · 3 节
为什么排在这里
┌────────┬──────┬──────────┬──────┬──────┬──────┬──────┐
│ 关键词 │ 标题 │ 条目标题 │ 路径 │ 章节 │ 摘要 │ 全文 │
├────────┼──────┼──────────┼──────┼──────┼──────┼──────┤
│ 上线   │      │          │      │  ✓   │  ✓   │  ✓   │
└────────┴──────┴──────────┴──────┴──────┴──────┴──────┘
命中要点 1 · 弱命中 2 · 只在全文里 0
```

**命中说明默认就展开，不做下拉。** 这一页存在的理由就是看它，藏在按钮后面只会多一步操作；
等真有第二类内容要折叠时再加下拉。列从 `docs/03` 的顺序取，不要自己发明。

有 bigram 近似命中时在计数下面再加一句：
`近似命中加了 3 分（中文没有分词，这里按两字一组补的）`。

空结果时的文案照抄：

> 这个词没有命中任何一篇文章。
> 先试试更短、更常见的说法；还是不行就在知识库页点「全部更新」重新整理一遍。
> 想看整个知识库有哪些文章，可以给 AI 说：用 kb-lite 列一下我的知识库。

数据来源：`POST /api/search`（管理面，UI 专用）。**不要**让 UI 直接打 `/kb/{name}/search`：
那条要访问密码，而界面手上只有管理凭据。agent 那一面仍然是 `/kb/{name}/search`，两边共用同一套打分。

### 5.4 Agent 视角页

把 **AI 真正收到的东西原样摊开**：用户不用信我们的描述，自己看。

入口：`#agent`。**导航里暂时不显示**（`web/src/views/AgentView.vue` 与路由都留着，要回来就加回 `tabs`）。
这一页是排查工具，日常用户不需要它。导航里的位置留给帮助页：新手第一个要看的是“怎么开始”，
而不是“AI 到底收到了什么”。
默认整页只显示一排“取一次”按钮，点了才请求，
因为四个请求加起来不小，而且用户不是每次都想看。

四块，每块一行标题、一个小按钮「取一次 / 重新取」、状态与 `Content-Type`，然后一个可滚动的 `<pre>`：

| 块 | 实际请求 | 给谁看 |
|---|---|---|
| AI 读到的说明书 | `GET /skill.md` | 这是 agent 第一步拿到的东西，里面有地址、密码、库列表 |
| 不知道搜什么词时 | `GET /kb/{name}/manifest?budget=800` | 预算内裁切的分层概览 |
| 一次检索 | `GET /kb/{name}/search?q=…&format=json` | 一个词的原始 JSON，含 `toc` |
| 一次按节阅读 | `GET /kb/{name}/entry/{path}/section?n=1` | agent 读完目录后的第二步 |

每块下面一行小字：

> 这几段是 AI 看到的原文，一个字都没改过。看不懂是正常的。

**谁去发这个请求**：服务端（`POST /api/preview`，管理面）。界面手上只有管理凭据，拿不到读取密码，
自己发会 401；而“代发”才能看到**真的**响应（包括 `Content-Type`、状态码与边界情况）。
为此这个接口必须白名单：只允许上表那几个 `kind`，`kb` 必须真的存在，`path` 必须是相对路径，
绝不能变成任意 URL 代理。响应超过 200 KB 就截断并注明。

### 5.5 设置页

| 项 | 行为 |
|---|---|
| 配置文件位置 | **只读**显示配置目录，行尾 `[操作|↓]`：打开文件夹位置、复制路径。**不写解释文案**：这一行只需要回答“东西在哪”，下面那行路径就是答案 |
| 端口 | 改完立刻重新监听。旧页面连不上时提示新地址并跳过去 |
| 谁可以打开 | 只有这台电脑，或同一个 WiFi 下的其他设备。选后者时自动打开访问密码 |
| 访问密码 | **只在「共享到局域网」或已经开着的时候出现**。只绑本机的人不需要被一个密码框打扰；但已经开着时必须能看见、能关掉，否则用户就锁不回去了。开着时给出可直接粘给 AI 的一段话 |
| 重新运行向导 | 把 `setupCompleted` 置 false 并跳到向导 |
| 开机自启 | 复选框。**v0.4 只做 Windows**（写 `HKCU\…\CurrentVersion\Run`，不需要管理员）。其他平台开关置灰并说明“这个系统还不支持”。下面一行小字把真正写进系统的命令原样显示出来 |
| 创建桌面快捷方式 | 按钮 + 现状。`GET /api/shortcut` 读 `.lnk` 的 `TargetPath`，与当前 exe 比一比：没建过 / 指向现在这份 / 指向另一份（那个文件可能已经不在了）。不一致时按钮变成「重新创建」并给一句警示 |
| 检查更新 | 显示当前版本 + 一个按钮。**全站唯一会访问外网的按钮**：点了才请求 GitHub 的 `releases/latest`，不随启动、不后台定时。有新版本给链接；查不到就说“这次没查到，可能没联网” |
| 日志 | 查看最近 200 行，打开日志目录。这一页是排查用的，可以技术腔（v0.5） |

开机自启那行下面要不要写解释？写。两句，按当前状态二选一：

> 登录后自动跑起来，托盘会出现。
> 关掉的话，每次开机要自己双击一次。

不支持的平台上照抄：

> 这个系统还不支持开机自启，暂时只能开机后自己打开一次。

**两个必须提醒的坑**（都是用户真会遇到的）：

1. **程序在下载或临时目录里**（`Downloads` / `Temp`）：那里随时会被清掉，自启下次开机就静默失效。
   照抄：“程序现在在下载或临时文件夹里，那里随时会被清掉。建议先把它挪到一个固定位置，再开开机自启。”
2. **自启指向的是另一份 kb-lite**：用户挪了文件、或又解压了一份新的，注册表里还是旧的路径。
   照抄：“开机自启现在指向另一份程序：<路径>。”下面配一个**改成指向现在这份**按钮。
   实现上就是把那个开关重写一遍（`POST /api/startup {enabled:true}`），写进去的永远是当前 exe。

**换新版本之后，这两个入口都不能自己变聪明，所以要在界面上显式比一次。**

用户升级的典型动作是“把新的 exe 解压到另一个文件夹”。于是：

| 入口 | 会指着旧版本的地方 | 怎么发现 |
|---|---|---|
| 开机自启 | `HKCU\…\Run\kb-lite` 里那条命令 | `GET /api/startup` 把注册表里的 exe 与当前 exe 比（`samePath`，会展开 Windows 的 8.3 短名），不一致就置 `mismatch` |
| 桌面快捷方式 | `KBLite.lnk` 的 `TargetPath` | `GET /api/shortcut` 读 `.lnk` 再比，同时看那个 target 还在不在（`missing`） |

两边都给同一个出口：**重写一次**。不给“改路径”这种半截能力：用户手上没有“编辑 .lnk”这件事的余地。
旧文件已被删掉的情况尤其要说明白，否则双击只会弹一个看不懂的系统错误。

**为什么不在启动时自动改**：那是替用户动他桌面上的东西，而用户可能是有意留着一个旧版本。
发现与提示是界面的事，改不改由用户点那个按钮。

关掉访问密码时**不显示提示，因为这一整块在不该出现的时候就不显示**（见上表）。
只绑本机的人本来也拿不到密码的作用：能改 `config.json` 的程序同样能读 `read-token`。

打开时的提示，照抄：

> 把下面这段话发给你的 AI，或填进它所在工具的配置里。少了它，AI 会连不上：
>
> `我的知识库服务在 http://127.0.0.1:7331，访问密码是 a1b2c3…`
>
> 一次性密码，别发给别人。点“换一个”，旧的就作废了。

**管理凭据，用户看不见**：UI 自己调管理接口用的是另一把 `api-token`，只以 `HttpOnly; SameSite=Strict` cookie 下发，界面上不显示也不可复制。用户看到、能复制的密码永远只是读取用的那一把。

保存时按顺序校验，任一步失败就回滚并指出是哪一步：

1. 端口可用。真的 bind 一次再放开。
2. 目标目录可写。建一个临时文件写完删掉。不能真的建 `index.db`，Windows 上它正被占用。
3. 原子写 `config.json`。
4. 重新监听。**先绑新地址，成功了才关旧的**；绑不上就回滚，旧地址继续服务并报错。

**保存成功要给反馈**：底部浮一条提示（几秒后自己消失），写“已保存。”；
只有“记录文件位置要重启才生效”这种不能自己消失的话，才留在页面里当提示条。
什么都不说是不行的：用户点完保存只看到页面没变，会以为没保存上，然后点第二遍。

### 5.6 帮助页（`#help`）

导航的**第二个**页签。新手最先要看的就是它，所以放在知识库旁边，而不是藏在设置里。

导航因此变成五个：“知识库 / 快速上手 / 检索测试 / 设置 / 关于”。320px 宽的窗口放不下，
所以 `nav` 自己横向可滚（`overflow-x-auto` + 每个页签 `whitespace-nowrap shrink-0`）。
**不要**为了塞下五个而缩字号或砍页签：横向滚比看不清强。

内容顺序（照抄，不要重新编排）：

1. 创建你的第一个知识库：三步、选目录、空目录也行、用户目录下的权限提醒。
2. 安装 SKILL：两组、三个按钮状态、什么时候会显示“有更新”、装完要重开会话。
3. 向知识库添加内容：让其他 AI 代劳（写不进就送回检查）、自己写（frontmatter 与标题规则）。
4. 版本更新：下载、替换 exe、看版本号、看自启与快捷方式指到了哪儿、看 SKILL 是否要更新。
5. 常见问题：先占位，指向 issue。

**不引 markdown 渲染器**。这一页的内容全是静态的、由我们自己写，只有一页：

- `markdown-it` 起步 40 KB，还要配 sanitize；
- 一旦有了 `v-html` 这条通道，迟早会有人拿它去渲染用户内容，而那是明令禁止的（AGENTS.md）；
- 手写标签多花几行，换掉一个依赖和一类风险。

样式写在组件的 scoped CSS 里（标题、列表、行内代码）：Tailwind 的 preflight 把列表符与标题字号都抹平了，
不写回来这一页会变成一堵墙。

### 5.7 访问日志页（`#logs`）

**不进导航**。它是排查工具，不是日常功能：入口两处，顶栏服务状态的下拉里一项，设置页“其他”里一条。
两处都是 `<a href="#logs">`，靠 hash 路由切换，不做二次跳转。

页面从上到下：

1. 标题“访问日志”，右侧“清空”按钮（要二次确认原文：清空之后不能恢复）。
2. 一句说明：谁在什么时候来查了什么。只记在内存里，kb-lite 重开就清空。
3. **隐私提示必须显眼**：`本信息只用于调试，不会提交到网络。` 用 `.note` 样式，不是灰色小字。
   日志里有搜索词，用户有理由担心它在往外传，所以这一句要写在他看见日志之前。
4. 表体，一行一条，新的在最上面。四列：时间（`HH:mm:ss`）、谁、方式、干了什么、状态码。
   - 谁：本机请求写“本机”，其它写反查到的设备名，后面用小字补 IP；反查不到就只写 IP。
   - 方式：命令行 / curl / 浏览器 / 其它程序 / 未知程序。鼠标悬停显示原始 User-Agent。
   - 干了什么：服务端给的 `action` 人话，例如 `在“笔记”里搜了“部署 回滚”`。超长截断，悬停看全文。
   - 状态码：4xx/5xx 用 `--danger` 上色，悬停显示耗时。
5. 底部：被覆盖掉的旧条目数、上限、当前条数。

刷新方式：页面可见时每 1.5 秒拉一次增量（`since=latest`）。页面在后台就不拉，切回来立刻补一次。
界面上最多留 500 行，再多浏览器会卡，而没人会往上翻几百条。

空状态：`还没有访问记录。让 AI 查一次，这里就会出现。`

## 六、状态刷新：快照比对

不引入 inotify 或 `fsnotify`。Windows 下目录多时句柄与 CPU 成本高，跨平台行为也不一致。增量整理本来只要 64 毫秒，251 篇实测。

- 待更新的判定：把当前目录扫一遍 `relPath`、`size`、`mtimeMs`，与索引记录比对。不读文件内容，不算 sha1。
- 触发时机：打开或刷新页面时；页面可见时每 5 秒一次；用户点“更新”后立刻重扫。
- 从没整理过时，同一套扫描也能给出“这个知识库有 128 篇，还没整理”。
- 不做后台自动重建。那属于后台维护任务，`docs/00` 明确不做。要自动，也只在用户点开 UI 时提示。

### 6.1 心跳与掉线

那次每 5 秒的 `GET /api/status` 同时是**心跳**：它回答“给我送页面的那个进程还在不在”。

页面的静态资源是那个进程给的，进程一退，页面就是一具还在动的尸体：界面上按钮都好好的，点下去全部失败。所以：

- 页面可见时每 5 秒探一次（整理中缩到 1 秒，要显示进度）。**页面在后台就停**，省电，也不制造无意义的请求。
- 切回前台立刻探一次，不等下一个心跳。
- **连续 2 次“请求发不出去”**才判定掉线。一次抖动不算。服务端能回 4xx/5xx 说明它还活着，那是另一种问题，不归这里管。
- 掉线时**整页替换**，不是弹 toast。用户正打算改设置，写操作一定失败，一个 3 秒就消失的提示拦不住他继续点。
  原文见 8.4。**不放“重新连接”按钮**：心跳本来就在自己重试，按钮点了也只会再失败一次，多一个按不动的按钮只会让人以为是坏事。
- 服务回来（用户重新打开 kb-lite，端口没变）时心跳成功，页面自己恢复，不需要手动刷新。
- 只做页面到服务端的单向探测。不上 WebSocket / SSE：要处理代理、同源校验、断线重连，换来的只是每 5 秒省一个几百字节的请求。服务端反过去探浏览器更不可能，浏览器没有可寻址的端点。

### 6.2 别开第二个标签页

双击 exe（等同于 `serve --open`）之前先问一句“有没有页面在看着”（`/api/status` 的 `uiAlive`）：

- **有页面**：不打开浏览器。用户双击的场景多半就是“页面还在，顶上写着 kb-lite 已关闭”，
  他真正要的就是那一页，它 5 秒内会自己恢复。这时候再开一个标签页，等于两个页面各自轮询、各自显示。
- **没页面**：正常打开。

判断不出来（拿不到凭据、超时、老版本服务端没这个字段）一律当作“没页面”。
宁可多开一个标签页，也不要双击之后什么都不发生：对不懂命令行的人来说，那等于程序坏了。

**不要靠托盘气泡做这件事的告知。** `Shell_NotifyIcon` 的 `NIF_INFO` 在 Win10/11 上会被系统转成通知中心的 toast，默认的专注助手一开就静默掉，用户也可能根本没在看托盘。
真正的告知是页面自己从“已关闭”变回正常界面，那比任何通知都直接。


## 七、外观

- 明暗两套，跟随系统。不要用 JS 取系统配色：`color-scheme: light dark` 与 `@media (prefers-color-scheme: dark)` 在首帧绘制前就生效，天然不闪。
- 用户手动覆盖时（设置里可选跟随系统、浅色、深色），在 `<head>` 放一小段同步脚本，读 `localStorage` 后给 `<html>` 加 `data-theme`。同步脚本同样在首帧前执行，也不闪。
- 设计 token：中性色阶加一个强调色，圆角 8 到 12 像素，字号阶梯 12、14、16、20、24。不要阴影堆叠，靠留白与边框分层。

## 八、文案：假定用户只会用 AI

> 这一节的优先级高于作者自己的语感。字数不够、术语不对就是 bug。

### 8.1 读者模型

写每一句话之前先想这个人：

- 会用 AI 聊天，会让 AI 帮忙改文件。但不知道什么是端口、接口、访问密码、索引。大概率也不知道自己的文件放在哪个盘。
- 不读文档，只读屏幕上的字。遇到看不懂的词就点取消，或者直接关掉。
- 判断这软件靠不靠谱，全靠界面说不说人话。

所以：不解释原理，只说会发生什么，和现在该做什么。

### 8.2 四条规则

1. 一句话只讲一个意思。先说结论，再说原因。
2. 界面上不出现技术名词。必须出现时放进“高级”或“给技术人员”里，默认收起。
3. 报错必须给下一步：发生了什么、为什么、现在点哪个按钮。只报“失败”等于没做。
4. 不吓人也不卖萌。不用三个感叹号堆情绪，不用“~”和表情装可爱。担心的地方用一句具体后果说明白。

行文细节（角括号、破折号、人称）见 `docs/11-writing-style.md`。

### 8.3 术语对照，照抄

| 界面上写 | 不要写 | 说明 |
|---|---|---|
| 知识库 | KB、实例、collection、笔记、笔记库 | **统一用“知识库”**。用户拿“笔记”去问 AI，AI 不认得 |
| 整理，正在整理 | 索引、切片、重建、reindex | 动词统一用“整理” |
| 更新一下 | 重新整理、刷新索引 | |
| 记录文件 | 缓存、index.db、SQLite | 一句“这里只存我们自己的登记信息” |
| 2 篇文档未成功入库 | skipped、被跳过、没被收录 | 点「查看入库日志」能看到名单与原因 |
| 访问密码 | token、key、Bearer、凭证 | 用户能看懂、能复制的那一把 |
| 端口 | 门牌号、port | 技术词保留，配一句“一般不用改” |
| 同一 WiFi 下的其他设备 | 局域网、0.0.0.0、Host 校验、CORS | |
| 打开地址，地址 | URL、endpoint、接口 | |
| 文件开头的设置 | frontmatter、元数据 | |
| 安装 SKILL | 技能、插件、prompt、system prompt | 按钮主文本就是 SKILL，次要文本解释给不懂的人 |
| SKILL 未安装 / SKILL 有更新 | 未安装、有新版 | 前面加上 SKILL，单独一行时才知道装的是什么 |

### 8.4 状态与错误文案，照抄

| 场景 | 界面上写 |
|---|---|
| 一个知识库都没有 | 还没有添加知识库。<br>副标题：选一个放着资料的文件夹，我们会把它整理成 AI 能查的形式。文件不会被改动。<br>按钮：添加知识库 |
| 根目录不见了 | 找不到 `D:\notes` 这个文件夹了，可能被删掉或改了名字。<br>按钮：重新选一个 |

| 关掉访问密码 | 见 5.4 的两段提示原文 |

### 8.5 给 AI 的内容要单独标注

UI 里凡是给 agent 用的内容（命令示例、SKILL 全文、说明书地址），都在块上方加一行：

> 这一段是给 AI 用的，你不用看懂。点“复制”把它粘给 AI 就行。

否则用户会盯着 JSON 怀疑自己装错了。

**验收方式**：把界面上所有文案抽成一张列表，给一个只会用 AI 的人看，问他两件事。第一，现在知道该点哪儿吗。第二，有没有哪个词不认识。两个问题有一个答不上来就重写。

## 九、明确不做

- 在 UI 里编辑 markdown。kb-lite 不做内容写入，编辑是用户编辑器或 git 的事。
- 在 UI 里聊天。没有 LLM。
- git 图形界面。最多在知识库这一行显示 git 状态与“拉取”按钮，排在 v0.5。
- 后台自动重建，或常驻文件监听。
- 系统通知打扰，必要的一次性提示除外。
- 中英双语。先只做中文，字符串集中管理。

## 十、CLI 平权清单

GUI 能做的，CLI 必须也能做。这张表是验收清单，任何一行缺 CLI 对应物，UI 那一项就不该存在。

| GUI | CLI |
|---|---|
| 添加、删除、改名、启用、禁用知识库 | `kb-lite add` / `remove` / `rename` / `enable` / `disable` |
| 更新、全部更新 | `kb-lite reindex <name>` / `reindex <name> --force` |
| 查看入库日志 | `kb-lite status`（按类别汇总告警，并列出跳过明细） |
| 复制路径 | `kb-lite list --json` 或 `kb-lite status`，两者都直接打印 `rootPath` |
| 打开文件位置 | **无 CLI**。路径由上面两条命令给出，打开窗口在无桌面的环境里没有意义 |
| 设置页各项 | `kb-lite settings`，可选 `--port`、`--host`、`--password on\|off` |
| 安装两份 SKILL | `kb-lite skill --install`、`kb-lite skill --install-authoring`（都可加 `--target dsh\|claude\|both`） |
| 启动、暂停、退出 | `kb-lite serve` / `stop` / `quit` |
| 打开界面 | `kb-lite serve --open` |
| 运行状态 | `kb-lite status [--json]` |
| 看访问日志、清空 | `kb-lite logs [--limit n] [--json]` / `kb-lite logs --clear` |
| 自检 | `kb-lite doctor` |
