# 06 · 界面（Web UI / 桌面壳）评估与规格

> 结论先说：**v1 不要 Tauri。** 用 daemon 自带的浏览器 UI + 一个自己实现的目录选择器就能覆盖你列的全部功能，安装摩擦为零。Tauri 留到 v2，触发条件和它的真实成本见下。

## 一、四条路线

| | A. 服务端自带 Web UI | B. 单文件 exe + 浏览器 | C. Tauri 壳 | D. Electron |
|---|---|---|---|---|
| 用户要装什么 | **不需要**（本地起个进程，浏览器打开） | 解压一个 exe | 安装包（含 WebView 依赖） | 安装包（自带 Chromium，~150 MB） |
| 是否挂全局 | 否 | 否 | 写注册表/启动项 | 同 C，更重 |
| 包体 | 0（UI 是 daemon 里几个静态文件） | **~12–18 MB**（Go 静态二进制） | ~8 MB + sidecar 18 MB | ~150 MB |
| 渲染一致性 | 用户浏览器（现代即可） | 同 A | Windows 靠 WebView2 / Linux 要 `webkit2gtk`（apt 装） | 完全一致 |
| 系统托盘 / 开机自启 | ❌ | ❌ | ✅ | ✅ |
| 原生目录选择 | ❌（见下） | ❌ | ✅ | ✅ |
| 签名成本 | 无 | 无 | **Windows 证书 / macOS 公证 = 真金白银** | 同 C |
| CI 复杂度 | 低 | 中（三平台交叉编译 SEA） | 高（Rust 工具链 + 三平台打包 + 签名） | 中高 |

### 关键的一条：桌面壳的「最大成本」不是开发，是签名

面向「屁代码都不懂」的用户，未签名意味着：

- **Windows**：SmartScreen 弹出「Windows 已保护你的电脑」，要点「更多信息 → 仍要运行」。懂行的人会点，不懂的人会**直接关掉并认为这是病毒**。
- **macOS**：未公证的 app 双击会被系统拒绝（「Apple 无法检查其是否包含恶意软件」），得右键打开或 `xattr -d com.apple.quarantine`。对一个免费开源项目来说，要求用户敲命令才能打开，和「开箱即用」是直接矛盾的。
- 解决要钱：Apple Developer Program **$99/年**；Windows 代码签名证书（OV）**几百美元/年**，EV 更贵。

本项目**不收钱**，所以这笔开销要么自己出，要么就接受「用户要点一下仍要运行」。这个决定必须在做 Tauri 之前定，不要等打包完了才发现。

### 关键的二条：目录选择器可以自己实现

浏览器确实拿不到真实路径（`showDirectoryPicker()` 返回 handle 不给路径，且只有 Chromium 支持）。但 daemon 有文件系统访问权，所以：

```
GET /api/fs/list?path=D:\notes   →  { dirs: [...], parent, drives }
```

UI 用它渲染一个**服务端驱动的目录浏览器**。这不但没有劣势，反而**比系统对话框更好**：可以在每个目录旁边显示「这里找到 12 个 markdown 文件」，用户选错目录的概率直接降下来。

### 触发升级到 Tauri 的条件

同时满足两条才值得做：

1. 用户明确反馈「关掉浏览器就找不到服务了」/「我想要个托盘图标」/「开机自动跑」；
2. 已经准备好签名预算，或者接受「未签名 + 图文指引」。

在那之前，先用 `kb-lite autostart enable`（写系统自启项，见下）覆盖「开机就要能用」这个 80% 的诉求。

## 二、v1 形态规格

**一个二进制，双击即起，浏览器自动打开。**

```
kb-lite serve --open
# 首次运行：没有 config → 自动进「初始化向导」
# 之后：直接进主界面
```

- 静态资源用 `//go:embed` 打进二进制（`web/dist` 构建后拷到 `internal/daemon/static/`）。
- 端口被占自动 +1；实际地址写进 `config.json`，UI 只从 `/api/status` 读，不硬编码。
- **UI 页面上直接注入 token**（`<meta name="kb-token" content="…">`），前端 fetch 时带上。用户永远不需要看见 token。
- 关闭浏览器标签页 = 只是关掉界面，daemon 还在跑（`kb-lite status` 能看到）。UI 里要有一行小字说明这件事，并给「退出 kb-lite」按钮。

### 为什么不用 Electron

我们唯一想要它是「渲染一致 + 托盘 + 原生对话框」，代价是 150 MB 和一个永远要跟着升级的 Chromium。对一个「索引几个 markdown 文件」的工具是不成比例的。**如果将来真要上桌面壳，用 Tauri。**

## 三、功能规格

### 3.1 首次启动向导（只出现一次）

```
第 1 步：数据放哪儿
  ○ 默认位置  <配置目录>/index.db            [推荐]
  ○ 自定义    [浏览…]

  说明文字（原话照抄，用户会读这一句）：
  「这里只存索引缓存。删掉它不会丢失你的任何笔记 —— 重建一下就好。」
第 2 步：第一个知识库
  目录  [浏览…]    名称 [自动取目录名]
  选择后立刻显示：✓ 在这个目录里找到 128 个 markdown 文件，共 2.1 MB
第 3 步：开始索引（进度条）→ 完成页
  完成页给出：
    · 可复制的完整 curl 示例（带 token、带你刚建的 KB 名）
    · 「复制给 Claude / Cursor 的 MCP 配置」按钮
    · 「复制给 Agent 的使用说明」按钮（= /skill.md 内容）
    · 「复制整理说明」按钮（= /authoring.md 内容：拿去让别的 AI 把 docx / pdf 转成这个格式）
```

**第 3 步是产品的最后一公里。** 非技术用户卡住的不是「接口怎么设计」，而是「我该怎么把它接进我的 agent」。所以：

- curl 示例必须是**能直接粘贴执行的完整命令**（含 `http://127.0.0.1:7331`、含 token、含中文 KB 名 URL 编码后的样子）；
- MCP 配置必须是**能直接存成 `.mcp.json` 的 JSON**（指向本地 HTTP endpoint，不是 stdio）；
- 四个按钮都只用「复制」，不要「下载文件」—— 下载之后用户还得找得到它在哪。

### 3.2 主界面

左侧：知识库列表。右侧：选中 KB 的详情。

每个 KB 卡片：

```
我的笔记                          [ 已开启 ● ]
D:\notes                        128 篇 · 743 节 · 2.1 MB
上次索引：3 分钟前               ⚠ 2 个文件被跳过

[重新切片]  [查看目录]  [搜索调试]  [删除]
```

- **开关**：切换 `enabled`。关掉时卡片变灰并显示「接口已关闭」，旁边一行小字：「文件不会被改动，重新开启也不需要重新索引。」
- **重新切片**：点一下开始，按钮变成进度条（`120 / 530`）；期间卡片显示「索引中，当前提供的是上一次的结果」。
- **删除**：二次确认对话框，包含**复选框「同时删除 xxx 个索引条目」默认勾选**，并明确写「**不会删除 `D:\notes` 里的任何文件**」。确认按钮写「删除关联」，不写「确定」。
- **目录**：展开一个树，可点条目看目录（复用 `/kb/{name}/entry/{path}` 的 `toc` 渲染）。
- **搜索调试**：输入框 + 结果表 + 每个结果展开看 `explain` 明细。这就是 CLI 的 `--explain`，图形化。

### 3.3 「Agent 视角」页（**不要砍掉这个**）

选中一个条目后，除了渲染后的 markdown，还要有一个页签，原样显示 agent 会拿到的东西：

```
[渲染] [Agent 视角]

GET /kb/我的笔记/entry/ops/runbook.md
{
  "title": "运维手册", "path": "ops/runbook.md", "rev": "a1b2c3d4",
  "sections": 4, "toc": "1 上线流程 · 1203 字\n2 回滚 · 空\n  3 快速回滚 · 380 字"
}

── 切片边界 ──────────────────────────────
section 0  导言                  412 字
section 1  上线流程             1203 字  ████████████
section 2  回滚                    0 字  ⚠ 空节（父标题）
section 3  快速回滚              380 字  ███
section 4  附录                 2215 字  ████████████████  ⚠ 超长，读取时会被截断
```

这是整个 UI 里**回报最高的一个功能**：用户加完内容之后 80% 的「怎么搜不到」都是切片问题（没有标题、层级太深、一节太长），而只有把边界画出来他才看得懂。

### 3.4 设置页

- 端口（改完提示需重启）
- 数据库位置（「更改位置」= 停止 → 复制/重建 → 改配置 → 重启；因为它是缓存，最省事的实现是**直接在新位置重建**）
- token：显示前 6 位 + 重新生成（生成后必须提示「所有已配置的 agent 都要换 token」）
- 「允许局域网访问」开关（默认关，打开时弹警告）
- 开机自启（Windows 写 HKCU Run 或计划任务、macOS `LaunchAgent`、Linux `systemd --user`）
- 日志：查看最近 200 行 / 打开日志目录

### 3.5 明确不做

- ❌ 在 UI 里编辑 markdown。kb-lite 是**只读**的；编辑是用户自己的编辑器或 git 的事。
- ❌ 在 UI 里聊天。没有 LLM。
- ❌ git 图形界面（v1）。最多在 KB 卡片上显示「git：有 3 个未提交改动 / 落后远端 2 个提交」和一个「拉取」按钮。

## 四、v2：Tauri 壳（若触发）

若做，只做三件事，别扩：

1. **托盘图标**：菜单 = 打开界面 / 重新索引全部 / 退出。关窗 = 收进托盘。
2. **开机自启 + 单实例**（第二次启动只把窗口提到前台）。
3. **原生目录选择**（`tauri-plugin-dialog`）。

实现要点：

- daemon 以 **sidecar** 形式打包（同一个 Go 二进制），由壳负责 spawn / 健康检查 / 退出时杀掉。**端口用 0 让系统分配**，通过 sidecar 的 stdout 打印实际端口交给壳，避免端口冲突。
- 壳与 daemon 通过同一个本地 HTTP 通信（`Authorization` 用壳自己生成的临时 token，不复用用户的）。
- 未签名分发时：README 里放**带截图的**「SmartScreen / Gatekeeper 提示怎么绕过」。这句话写了，用户才不会被拦在门口。
