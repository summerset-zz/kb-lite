# 06 · 界面：Web UI 与纯 Go 托盘

> **一个 Go 二进制**。UI 是 `//go:embed` 进去的静态资源，用系统浏览器打开。Windows 上同一个进程再挂一个托盘图标。
> 不上 Tauri 或 Electron，理由见第一节与 ADR-014。
>
> 本文合并了 `GUI-DESIGN.md` 的设计稿，并补齐了原稿没覆盖的规格。实现以本文为准。
> **UI 能做的事，CLI 必须也能做**（`docs/05`）。UI 只是 `/api/*` 的一个客户端，不许有自己的业务逻辑。
> 行文与文案遵循 `docs/11-writing-style.md` 与本文第八节。

## 一、为什么不上 Tauri

| | 浏览器 UI（采用） | Tauri 壳 | Electron |
|---|---|---|---|
| 用户要装什么 | 不需要 | 安装包 + WebView 运行时 | 安装包，自带 Chromium，约 150 MB |
| 包体 | 约 11 MB | 约 11 MB + sidecar 11 MB | 约 150 MB |
| 一台机器出全部平台产物 | 可以 | **不行**，不能从 Windows 交叉编译出 macOS | 可以 |
| 托盘 | 纯 Go 自己实现（Windows） | 有 | 有 |
| 签名 | 不需要 | Windows 证书与 macOS 公证都要钱 | 同左 |

三条否决理由，任一条单独成立就够了。

1. **交叉编译断了**。`docs/08` 里“一台 Windows 出五个平台的二进制”是换 Go 换来的最大收益。Tauri 要 Rust 工具链，且必须每平台各自构建。
2. **签名**。未签名的 Tauri 包在 Windows 被 SmartScreen 拦，在 macOS 被 Gatekeeper 拒。本项目不收钱，这笔开销没人出。
3. **它换来的只是托盘**。Windows 上 `Shell_NotifyIcon` 纯 `syscall` 就能做，不需要 cgo，也不影响交叉编译。

macOS 与 Linux 的托盘需求若真的出现（`docs/09` 的 v2 条件），再评估 Tauri。那时也要先把签名预算定下来。

## 二、进程形态

一个进程（`kb-lite serve`）同时做四件事：扫描切片、HTTP 服务、托管 UI、托盘（Windows）。没有 sidecar，没有第二个进程。

```
kb-lite serve            # 前台进程：监听、索引、托盘（Windows 上自动挂）
kb-lite serve --open     # 额外打开默认浏览器到 UI
```

- **关闭浏览器标签不等于退出**。daemon 还在跑，托盘图标还在。UI 里要有一行小字说明，并给“退出 kb-lite”按钮。
- **暂停服务与退出是两个动作**，托盘、UI、CLI 三处叫法必须一致：
  - 暂停服务：关掉 HTTP 监听。进程、索引、托盘都保留。再点启动立刻恢复，不重新整理。对应 `kb-lite stop`。
  - 退出：关监听，关记录文件，进程结束。对应 `kb-lite quit`。
- **单实例**：`<配置目录>/lock` 里写 pid 与实际端口。重复双击或重复 `serve` 时，探 lock 里的端口，能连上就把 UI 打开并退出自己。
- 端口被占自动加一，实际端口写回 `config.json`。UI 一律从 `/api/status` 读地址，不硬编码。

## 三、技术栈（ADR-016）

| 项 | 选择 | 约束 |
|---|---|---|
| 构建 | Vite + Vue 3 + TypeScript | 产物 `web/dist` 拷到 `internal/daemon/static/`，再 `//go:embed`。用户侧永远不需要 Node |
| 样式 | Tailwind CSS v4 | 设计 token 与组件级样式写在 `web/src/styles.css`，不引 CSS-in-JS |
| 交互原语 | 原生 `<dialog>`（v0.3） | 只买焦点陷阱、Esc 关闭、无障碍；这三件浏览器已经做对了，所以**先不引 Reka UI**。等真需要弹层锚点定位再引，别为两个弹窗拖进一整套组件库 |
| 图标 | 暂用文字按钮（v0.3） | `@iconify-json/lucide` 要配 `unplugin-icons` 才按需引入；等界面稳定后再补，不为图标多一层构建 |
| 禁止 | SSR、Nuxt、Element Plus、Naive UI、Ant Design | 这不是后台管理系统，也不要为一个本地工具拖进整套组件生态 |

硬规则：

- 禁止用 `innerHTML` 渲染任何来自知识库或用户输入的内容。markdown 预览走消毒过的渲染器，禁用原始 HTML。
- 字符串集中在 `strings.ts`。先只做中文，不散落在组件里。
- 网络调用收敛到 `api.ts` 一层，组件里不出现裸 `fetch`。

## 四、托盘（Windows）

图标只有两态：运行中、未运行。不做“处理中”的第三态。Windows 上频繁重绘托盘图标观感很差，动画帧更糟。进度属于窗口内的信息。

右键菜单，自上而下：

```
已在 http://127.0.0.1:7331 运行          ← 可点的普通项：点击复制地址并弹气泡
──────────────────────────────────
暂停服务 / 启动服务
正在索引 120 / 530                       ← 仅索引进中时出现，点击打开 UI
设置                                     ← 打开浏览器到设置的地址
在命令行中打开                            ← 打开终端到程序所在目录并跑一次 kb-lite -h
──────────────────────────────────
退出
```

约束：

- 不做灰掉的 disable 项。地址那一条可点复制，索引进度那一条可点打开界面。
- 双击托盘打开 UI。UI 的默认首页就是知识库页，设置是它里面的一页。
- 不弹系统通知，“已复制”这类一秒气泡除外。整理完成不打扰用户。
- 实现要点：隐藏窗口加消息循环，调 `user32` 与 `shell32`，不加 cgo。平台代码放 `_windows.go`，其他平台编空实现。
- macOS 与 Linux 暂不提供托盘，用 `kb-lite autostart enable` 加 `serve --open` 覆盖“开机就要能用”。

## 五、页面

### 5.1 首次启动向导（只出现一次）

判定条件：`config.json` 不存在，或 `setupCompleted` 为 false。之后可以在设置页重新运行向导。

**第 1 步 · 数据放在哪**

```
○ 默认位置  <配置目录>/index.db            [推荐]
○ 自定义    [浏览…]
```

说明文字照抄：

> 这里只存索引缓存。删掉它不会丢失你的知识库文件，重建一下就好。

**第 2 步 · 端口与访问范围**

```
端口  [7331]  [换一个]
     端口一般不用改。被别的软件占用时会自动换一个。
谁可以打开：
  ● 只有这台电脑
  ○ 同一个 WiFi 下的其他设备也能打开
```

选了第二项才出现的红字：

> [!WARNING]
> 打开后，同一个网络里的人只要知道地址就能看到你的知识库。不推荐。
> 如果你确实需要，比如想用手机上的 AI，会自动帮你打开访问密码。

**第 3 步 · 第一个知识库、开始整理、完成页**

完成页给出四个按钮，只复制，不下载文件：

| 按钮 | 内容 |
|---|---|
| 复制命令示例 | 一条可直接粘贴执行的命令。按当前访问密码设置决定是否带 `Authorization` |
| 复制给 AI 的说明书 | `/skill.md` 的全文 |
| 复制 MCP 配置 | 可直接存成 `.mcp.json` 的 JSON，指向本地 HTTP 地址 |
| 复制整理说明 | 写作 skill（`/authoring.md`）的全文 |

第 3 步是产品的最后一公里。用户卡住的从来不是接口设计，而是怎么接进自己的 AI。

### 5.2 知识库页（默认首页）

列表每行：

```
我的知识库                                            [已开启 ●]
D:\notes                     128 篇 · 743 节 · 2.1 MB
上次整理：3 分钟前            ⚠ 2 个文件没被收录 · 3 篇待更新
                                                      [操作 ▾]
```

显示项：名称、绝对路径、条目与节数、占用大小、上次整理时间、告警与未收录数、待更新标记。

操作（行尾下拉）：

| 操作 | 说明 |
|---|---|
| 打开所在文件夹 | 用系统文件管理器打开根目录 |
| 启用或禁用 | 关掉后这个知识库的 `/kb/…` 全部返回 `503 kb_disabled`。文件与索引都不动，重新开启不需要重新整理 |
| 更新 | 增量整理。只重切 sha1 变过的文件（`reindex` 不带 force） |
| 全部更新 | 全量重切（`force: true`） |
| 删除 | 二次确认。必须写明不会删除 `D:\notes` 里的任何文件，确认按钮写“移除”而不是“确定” |

- **命名**：名称默认取路径最后一段。重名自动加序号，写成 `notes (2)`、`notes (3)`，对话框里可以改。校验沿用 `docs/04`：1 到 64 字，不含 `/`、`\` 与控制字符，且唯一。
- **目录选择器**走 `GET /api/fs/list`，由服务端列目录，不是系统对话框。每个目录旁边显示“这里有 12 个 markdown 文件”，减少选错目录。

**SKILL 区块**：两个独立按钮，不要合并。

| 按钮主文本 | 次要文本 | 装什么 | 装到哪 |
|---|---|---|---|
| 安装 SKILL / 更新 SKILL | 让 AI 能查这个知识库 | `/skill.md` 渲染结果 | `~/.agents/skills/kb-lite/SKILL.md`（DSH 读这里），可选再装一份到 `~/.claude/skills/kb-lite/SKILL.md` |
| 安装整理 SKILL / 更新整理 SKILL | 让 AI 把文件整理成这个格式 | `docs/authoring-template.md` 渲染结果 | `~/.agents/skills/kb-lite-authoring/SKILL.md` |

每个按钮下面给一句可以直接说给 AI 听的话，点一下复制：

- 检索：用 kb-lite 去我的知识库里查一下……
- 整理：用 kb-lite-authoring 把这些文件整理成可以进知识库的格式

按钮下方一行小字：装好后要重启一次 AI 工具才会生效。

> [!NOTE]
> 两份 SKILL 必须分开装（ADR-017）。把写作规范塞进检索 SKILL 里，agent 会在只想查东西的时候也去改用户的文件。

**运行状态区**：地址（可复制）、哪些设备可访问、当前状态（ready、indexing、error、disabled）、整理进度。

页脚：`KBLite vX.Y.Z`、作者 [Summerset-zz](https://github.com/summerset-zz)、[反馈问题](https://github.com/summerset-zz/kb-lite/issues)、检查更新（v1 先占位）、支持作者。

### 5.4 设置页

| 项 | 行为 |
|---|---|
| 记录文件位置 | “换个位置”会在新位置重新整理。它是缓存，不需要搬文件。成功后删旧文件，失败就留着 |
| 端口 | 改完立刻重新监听。旧页面连不上时提示新地址并跳过去 |
| 谁可以打开 | 只有这台电脑，或同一个 WiFi 下的其他设备。选后者时自动打开访问密码 |
| 访问密码 | 默认关。开着时 AI 必须带上密码才连得上，界面给出可直接粘给 AI 的一段话；关着时说明危险在哪 |
| 重新运行向导 | 把 `setupCompleted` 置 false 并跳到向导 |
| 开机自启 | Windows 写 HKCU Run 或计划任务；macOS 用 `LaunchAgent`；Linux 用 `systemd --user` |
| 日志 | 查看最近 200 行，打开日志目录。这一页是排查用的，可以技术腔 |

关掉访问密码时的提示，照抄：

> 关掉之后，这台电脑上的任何程序都能读你的知识库。你浏览器里打开的网页不行，它们打不开这个服务。
> 选“同一个 WiFi”时会自动打开，没得关。

打开时的提示，照抄：

> 把下面这段话发给你的 AI，或填进它所在工具的配置里。少了它，AI 会连不上：
>
> `我的知识库服务在 http://127.0.0.1:7331，访问密码是 a1b2c3…`
>
> 一次性密码，别发给别人。点“换一个”，旧的就作废了。

**管理凭据，用户看不见**：UI 自己调管理接口用的是另一把 `api-token`，只以 `HttpOnly; SameSite=Strict` cookie 下发，界面上不显示也不可复制。用户看到、能复制的密码永远只是读取用的那一把。

保存时按顺序校验，任一步失败就回滚并指出是哪一步：

1. 端口可用。真的 bind 一次再放开。
2. 目标目录可写。建一个临时文件写完删掉。不能真的建 `index.db`，Windows 上它正被占用。
3. 原子写 `config.json`。
4. 重新监听。失败则恢复旧端口并报错。

### 5.5 标题

浏览器里不自绘标题栏。页面顶部一条 `KBLite by Summerset-zz` 的页头即可。浏览器标签页标题写 `KBLite · 我的知识库`，favicon 用 `web/public/favicon.svg`。

## 六、状态刷新：快照比对

不引入 inotify 或 `fsnotify`。Windows 下目录多时句柄与 CPU 成本高，跨平台行为也不一致。增量整理本来只要 64 毫秒，251 篇实测。

- 待更新的判定：把当前目录扫一遍 `relPath`、`size`、`mtimeMs`，与索引记录比对。不读文件内容，不算 sha1。
- 触发时机：打开或刷新页面时；页面可见时每 5 秒一次；用户点“更新”后立刻重扫。
- 从没整理过时，同一套扫描也能给出“这个知识库有 128 篇，还没整理”。
- 不做后台自动重建。那属于后台维护任务，`docs/00` 明确不做。要自动，也只在用户点开 UI 时提示。

## 七、外观

- 明暗两套，跟随系统。不要用 JS 取系统配色：`color-scheme: light dark` 与 `@media (prefers-color-scheme: dark)` 在首帧绘制前就生效，天然不闪。
- 用户手动覆盖时（设置里可选跟随系统、浅色、深色），在 `<head>` 放一小段同步脚本，读 `localStorage` 后给 `<html>` 加 `data-theme`。同步脚本同样在首帧前执行，也不闪。
- 设计 token：中性色阶加一个强调色，圆角 8 到 12 像素，字号阶梯 12、14、16、20、24。不要阴影堆叠，靠留白与边框分层。

## 八、文案：假定用户只会用 AI

> 这一节的优先级高于作者自己的语感。字数不够、术语不对就是 bug。

### 8.1 读者模型

写每一句话之前先想这个人：

- 会用 AI 聊天，会让 AI 帮忙改文件。但不知道什么是端口、接口、访问密码、索引。大概率也不知道自己的文件放在哪个盘。
- 不读文档，只读屏幕上的字。遇到看不懂的词就点取消，或者直接关掉。
- 判断这软件靠不靠谱，全靠界面说不说人话。

所以：不解释原理，只说会发生什么，和现在该做什么。

### 8.2 四条规则

1. 一句话只讲一个意思。先说结论，再说原因。
2. 界面上不出现技术名词。必须出现时放进“高级”或“给技术人员”里，默认收起。
3. 报错必须给下一步：发生了什么、为什么、现在点哪个按钮。只报“失败”等于没做。
4. 不吓人也不卖萌。不用三个感叹号堆情绪，不用“~”和表情装可爱。担心的地方用一句具体后果说明白。

行文细节（角括号、破折号、人称）见 `docs/11-writing-style.md`。

### 8.3 术语对照，照抄

| 界面上写 | 不要写 | 说明 |
|---|---|---|
| 知识库 | KB、实例、collection、笔记、笔记库 | **统一用“知识库”**。用户拿“笔记”去问 AI，AI 不认得 |
| 整理，正在整理 | 索引、切片、重建、reindex | 动词统一用“整理” |
| 更新一下 | 重新整理、刷新索引 | |
| 记录文件 | 缓存、index.db、SQLite | 一句“这里只存我们自己的登记信息” |
| 有 2 个文件没被收录 | skipped、被跳过 | 点开能看原因 |
| 访问密码 | token、key、Bearer、凭证 | 用户能看懂、能复制的那一把 |
| 端口 | 门牌号、port | 技术词保留，配一句“一般不用改” |
| 同一 WiFi 下的其他设备 | 局域网、0.0.0.0、Host 校验、CORS | |
| 打开地址，地址 | URL、endpoint、接口 | |
| 文件开头的设置 | frontmatter、元数据 | |
| 安装 SKILL | 技能、插件、prompt、system prompt | 按钮主文本就是 SKILL，次要文本解释给不懂的人 |

### 8.4 状态与错误文案，照抄

| 场景 | 界面上写 |
|---|---|
| 一个知识库都没有 | 还没有添加知识库。<br>副标题：选一个放着资料的文件夹，我们会把它整理成 AI 能查的形式。文件不会被改动。<br>按钮：添加知识库 |
| 根目录不见了 | 找不到 `D:\notes` 这个文件夹了，可能被删掉或改了名字。<br>按钮：重新选一个 |
| 没有写权限 | 这个文件夹不能写入。换一个位置试试，比如“文档”下面的文件夹。 |
| 端口被占用 | 端口 7331 被别的软件占了，已经改用 7332。新地址：`http://127.0.0.1:7332` |
| 正在整理 | 正在整理 120 / 530。<br>副标题：整理期间 AI 查到的是上一次的结果。 |
| 整理失败 | 这次没整理成：`<原文>`。<br>按钮：再试一次、打开文件夹看看 |
| 记录文件写不进去 | 记录存不下来，不影响使用，但下次启动会慢一点。<br>链接：查看详情 |
| 服务已暂停 | 服务已经暂停，AI 现在连不上。<br>按钮：继续使用 |
| 删除知识库 | 标题：要把这个知识库从列表里移除吗？<br>正文：只会删掉我们自己的登记信息和整理结果。<br>加粗：`D:\notes` 里的文件一个都不会动。<br>按钮：移除、算了 |
| 关掉访问密码 | 见 5.4 的两段提示原文 |

### 8.5 给 AI 的内容要单独标注

UI 里凡是给 agent 用的内容（命令示例、SKILL 全文、MCP 配置），都在块上方加一行：

> 这一段是给 AI 用的，你不用看懂。点“复制”把它粘给 AI 就行。

否则用户会盯着 JSON 怀疑自己装错了。

**验收方式**：把界面上所有文案抽成一张列表，给一个只会用 AI 的人看，问他两件事。第一，现在知道该点哪儿吗。第二，有没有哪个词不认识。两个问题有一个答不上来就重写。

## 九、明确不做

- 在 UI 里编辑 markdown。kb-lite 不做内容写入，编辑是用户编辑器或 git 的事。
- 在 UI 里聊天。没有 LLM。
- git 图形界面。最多在知识库这一行显示 git 状态与“拉取”按钮，排在 v0.5。
- 后台自动重建，或常驻文件监听。
- 系统通知打扰，必要的一次性提示除外。
- 中英双语。先只做中文，字符串集中管理。

## 十、CLI 平权清单

GUI 能做的，CLI 必须也能做。这张表是验收清单，任何一行缺 CLI 对应物，UI 那一项就不该存在。

| GUI | CLI |
|---|---|
| 添加、删除、改名、启用、禁用知识库 | `kb-lite add` / `remove` / `rename` / `enable` / `disable` |
| 更新、全部更新 | `kb-lite reindex <name>` / `reindex <name> --force` |
| 设置页各项 | `kb-lite settings`，可选 `--port`、`--host`、`--db`、`--password on\|off` |
| 安装两份 SKILL | `kb-lite skill --install`、`kb-lite skill --install-authoring`（都可加 `--target dsh\|claude\|both`） |
| 启动、暂停、退出 | `kb-lite serve` / `stop` / `quit` |
| 打开界面 | `kb-lite serve --open` |
| 运行状态 | `kb-lite status [--json]` |
| 自检 | `kb-lite doctor` |
