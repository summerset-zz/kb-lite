# 10 · 决策记录（ADR）

每条格式：**结论 → 理由 → 被否掉的方案 → 什么时候应该重新考虑**。
写给之后的实现者：如果你不同意某条，请先读完“理由”，不要直接改代码。

---

## ADR-001 不做向量检索

**结论**：永不引入 embedding / 向量库 / 语义相似度。

**理由**

1. “本地、离线、不要 API key”是产品的前提，而 embedding 一定需要模型（本地模型 = 几百 MB 下载 + GPU/CPU 推理，云模型 = 要 key 要联网）。
2. 目标内容规模是**几千篇**，不是几百万 chunk；关键词 + 结构位置加权在这个量级上召回足够。
3. 可解释性：`--explain` 能一行一行告诉用户“为什么这条排第一”。向量做不到，而这是用户自助排查的唯一途径。
4. 已有实证：同类项目（basic-memory）上向量是为了“跨笔记找意思相近的东西”，而我们的使用者真正的问题是“我记得写过 X，在哪一篇”。

**重新考虑的条件**：有 ≥ 3 个用户报告“用不同措辞搜不到明明存在的段落”，且这个比例在 `--explain` 日志里可量化。届时也是**加一层可选重排**，不是替换现有打分。

## ADR-002 不用 FTS5 / BM25，用自研加权计数

**结论**：检索 = 关键词 × 字段位置的加权计数（见 03）。不用 SQLite FTS5、不用 tantivy。

**理由**

1. **中文**：FTS5 的 `unicode61` 把连续汉字当一个 token，`trigram` 又要求查询 ≥3 字且索引膨胀。要正常用就得带分词器（原生依赖），和“零依赖”冲突。
2. **行为一致性**：这套打分在线上跑过很久，被真实 case 调过（`TypedArray.map` 压 `Array.map`、只命中摘要的不该和命中文档标题的同分）。换 BM25 等于把这些调优全部作废。
3. **规模够用**：全表扫 5000 篇 × 5 关键词 < 20 ms。

**重新考虑的条件**：单库 > 50000 篇。届时先上 `--fast` 粗筛（字符串 `includes`），仍不达标才考虑 FTS5。

## ADR-003 目录即真相，SQLite 是缓存

**结论**：删掉 `index.db` 只损失启动时间，不损失任何数据。UI 文案必须如实这么说。

**理由**：用户的核心恐惧是“我的笔记被这个工具怎么了”。把 DB 定义为缓存，可以直接消除这个恐惧，并且让“换 DB 位置”变成零风险操作。

**推论**：任何“只能从 DB 恢复”的信息都不许存在。KB 列表与配置在 `config.json`，不在 DB 里。

## ADR-004 只读

**结论**：不提供任何写文件、删文件的接口。

**理由**

1. 给 agent 写权限意味着它会改用户的笔记，而这类误操作**不可撤销地伤害信任**（同类项目为此要发明 talk page、session、审计日志一整套东西，见 llm-wiki 的下场）。
2. 用户的编辑工具已经很好（Obsidian / VS Code / vim）；我们再加一个只会做出一个更差的编辑器。
3. 只读直接把一半的攻击面消掉了。

**推论**：管理接口（增删 KB）是给**人**用的，和给 agent 的 `/kb/*` 在路径上分开，且永不出现在 skill 文档里。

**例外（v0.4 起）**：`POST /api/fs/mkdir` 会在用户正在浏览的那个目录里建一个**空文件夹**。
它不写文件、不改已有内容、不删任何东西，且只在管理面、只接受单个合法目录名。
理由在界面：用户在“选一个放着资料的文件夹”里发现那个文件夹还不存在，这时候让他切到资源管理器
建完再回来，是最容易放弃的一步。给 agent 的那一面（`/kb/*`）依旧只有读。

## ADR-005 单 daemon + 纯 HTTP，CLI 是薄客户端

**结论**：一个常驻进程持有索引；CLI 与 UI 都是它的客户端。

**理由**：多个进程要共享同一份索引与缓存，这在进程内是做不到的。MCP stdio 类工具只能每个客户端 spawn 一份，为此要先解决进程间共享（basic-memory 上了 Redis 缓存），复杂度陡增。

---

## ADR-006 MCP 是薄壳，不是内核

**结论**：内核只有 HTTP。若要做 MCP，做一个把调用原样转发到本地 HTTP 的 stdio 壳（30 行级别）。

**理由**：MCP 已经是事实标准，不提供会丢掉一部分用户；但把它做成第二种实现会导致两套行为漂移。薄壳不构成维护负担，且**多进程共享索引**的能力只有 daemon 才有。

---

## ADR-007 v1 用浏览器 UI，不上 Tauri

详见 [06](./06-desktop-ui.md)。**核心论据**：桌面壳的真实成本是**签名/公证**，不是开发；而免费项目付不起，未签名会直接劝退目标用户。

**重新考虑的条件**：用户明确要求托盘/开机自启，且准备好了签名预算或接受未签名分发。

---

## ADR-008 不做权限，多人协作交给 git

**结论**：没有账号、没有登录、没有多租户。

**理由**：目标用户是“一台机器跑服务，几个人往里改文件”。他们已经有 git 或共享盘；我们再加一套权限体系只会造出一个更差的协作工具。

**推论**：kb-lite **不提供任何 git 命令，也不碰 `.git`**。曾经计划过 `kb-lite sync`（`git pull --ff-only` 再 reindex）与卡片上的 git 状态，`v0.5` 时取消（[09](./09-roadmap.md#取消v05--git)）：一碰冲突就得把 git 的原始输出丢给用户，那已经超出“配置面板”的范围，而收益只是省两次点击。pull 之后要不要自动 reindex、失败怎么回滚、本地改动怎么办，每条都要一套交互，等于写半个 git 客户端。

## ADR-009 章节编号全局扁平，超长节不拆

**结论**：`0,1,2,3…` 连续编号，不出现 `1.1`。超长节用 `offset/maxChars` 读取，不产生子编号。

**理由**：编号是 agent 与人之间唯一稳定的引用物（toc → `section?n=`）。任何会让编号随内容变化的设计都是错的。层级信息已经在 `path` / `pathText` 里，不靠编号表达。

## ADR-010 “错误即数据”

**结论**：对 agent 的接口，在“你查的东西不存在”时不抛 4xx，而是 `200 + {ok:false, error, candidates}`。

**理由**：调用方是模型。404 会让它重试或放弃；把“不能这么查”和“你可以试这些”直接端给它，它下一次就对了。线上实测：改成候选清单后，同类问题的工具调用次数明显下降。

---

## ADR-011 `internal/core` 不 import 任何 I/O 包

**结论**：core 里没有 `net/http`、没有 `os`、没有 `path/filepath`、没有 SQLite 驱动。

**理由**：① 强迫把“读取”和“理解”分开，测试不需要 mock 文件系统；② 纯函数能被表驱动 / fuzz 直接压；③ 它将来要能被编成 WASM 给别的前端用（那是 v2 的事，但不要提前把这扇门焊死）。

> 原版的两条理由（“UI 可以直接复用做切片预览”“线上版原样复用”）在换 Go 后都不成立了。UI 改走 `POST /api/preview/slice`，线上版改走“共用规格 + 快照”，见 ADR-013。

---

## ADR-012 一次性全表打分，不做分档召回

**结论**：给所有条目完整打分再排序。

**理由**：线上版必须分 4 档逐步捞候选，是因为 MongoDB 的 `find().limit()` 不排序。最松那档动辄上千条，任意取 400 条会让真正的候选进不了窗口。本地是全表扫，这个限制不存在，召回严格更优。

**保留**：`--fast` 模式（> 50000 篇）下可以退化成粗筛 + 精算。

---

## ADR-013 服务端用 Go

**结论**：`core` / `daemon` / `cli` 用 **Go ≥ 1.22** 实现，产出单个静态二进制。前端保持 Vite + Vue，产物用 `//go:embed` 打进二进制。

**理由**

 1. **对用户影响最小。** 用 TS 意味着用户要么装 Node（22.5+ ），要么下载 80–110 MB 的 Node SEA 单文件。Go 是 ~11 MB（实测 10.6–11.5 MB，含纯 Go SQLite；zip 后 4.9 MB）、零安装、双击即用。目标用户里有一大批“完全不懂代码”（[00](./00-vision.md)），装运行时对他们不是成本问题，是**放弃**问题。
2. **交叉编译。** Node SEA 不能交叉编译，5 个目标要 5 个原生 runner；Go 在 Windows 上一台机器出全部产物（[08](./08-build-release.md)）。这直接砍掉 CI 里最容易烂掉的一块。
3. **启动时间**：Go ~5 ms vs Node 40–120 ms。v0.1 的验收标准是“300 篇启动到可服务 < 3 s”，Go 让这条不再是风险项。
4. **部署形态本来就只需要一个 HTTP 进程。** 我们没有动态加载的插件、没有用户提供的 JS、不需要 npm 生态。用 TS 的唯一硬理由是“线上版能复用同一份代码”，而那件事的真正价值在**规格与快照**，不在源码共享（见下）。
5. **标准库够用**：`net/http` 的 `ServeMux`（1.22 起支持方法 + `{path...}`）、`//go:embed`、`crypto/sha1`、`encoding/json`、`unicode`。对应过来正好是 04 要求的那些端点与 02 的逐行扫描。

**被否掉的方案**

| 方案 | 为什么不 |
|---|---|
| **TS + Node**（原方案） | 用户要装 Node，或 80–110 MB 单文件；SEA 还要每平台自建 + 去签名 |
| **TS + Bun `--compile`** | 交叉编译与 60–100 MB 单文件都比 Go 差；且 `bun:sqlite` 会把 core 锁进 Bun 运行时，反而更不通用 |
| **Rust** | 单文件与性能都对，但编译时间、CI、以及与维护者已有技能的差距都不成比例。本项目的计算量根本不需要 Rust |
| **Python + PyInstaller** | 产物与启动速度都差，且 PyInstaller 的三平台打包是出了名的脆 |
| **C# / .NET AOT** | 产物可以很小，但 Linux 上要匹配 ICU / 裁剪配置，维护者也不熟 |

**已知代价（接受）**

- **RE2 没有 lookbehind / lookahead**：03 里标识符词边界 `(?<![A-Za-z0-9_$])kw(?![A-Za-z0-9_$])` 写不成正则。改为“找出现位置 + 检查前后 rune”的手写判断，行为等价且更快。**新增正则前先确认 RE2 能表达。**
- **没有 ICU `localeCompare`**：排序第三级（title 字典序）改为按 rune 码点比较。确定性、可复现，但和线上版的具体顺序不同。它只是 score 之后的 tie-breaker，影响面小；且快照以新实现为准生成。
- **线上版无法复用源码**：改成“共用规格 + 共用排序快照 fixture”。这比共享代码更强。共享代码只保证“同样的 bug”，共享快照才保证“同样的正确”。
- **UI 不能直接调 core 做实时切片预览**：改走 daemon 的 `POST /api/preview/slice`（本地回环，< 1 ms）。
- **维护者不熟 Go**：语言小、标准库正、第三方依赖被限制在三个纯 Go 包里，项目总量约 2500 行。学习成本一次性，且远小于“每个用户装运行时”的持续成本。

**重新考虑的条件**：① Go 的维护成本实际压过了收益（例如每次改 core 都要重新学一遍）；② 出现必须复用线上 TS 实现的硬需求（例如要跟线上共用同一份插件代码）。

## ADR-014 托盘用纯 Go 自己实现（Windows 先行），不上 Tauri

**背景**：ADR-007 把 Tauri 留到 v2，触发条件是“用户明确要托盘/开机自启”+“签名预算”。现在前半条触发了。

**决定**：**Windows 托盘用 `user32` / `shell32` 的 `syscall` 自己实现**（`Shell_NotifyIcon` + 隐藏窗口消息循环），**不加 cgo**。UI 仍然开在系统浏览器里。macOS / Linux 暂时不提供托盘，用 `autostart` + `serve --open` 覆盖。

**理由**

1. Tauri 要 Rust 工具链，且**不能从 Windows 交叉编译出 macOS**。`docs/08` 的“一台机器出五个平台”直接破功；
2. 托盘在 Windows 上是 Win32 的十行 API，Tauri 为它拖进一整套运行时与签名成本（未签名的安装包在 SmartScreen / Gatekeeper 面前就是劝退）；
3. 单进程：daemon 与托盘同生共死，没有 sidecar、没有健康检查、没有第二套端口协商。

**代价（接受）**

- 原生消息循环不能单测，只能靠手测；托盘代码要包在一个平台文件里（`_windows.go`），非 Windows 编到空实现；
- macOS / Linux 用户没有托盘；
- 将来若要跨平台托盘，仍是 ADR-007 的路线（Tauri），**届时先定签名预算**。

## ADR-015 读取面 token 默认关，管理面用独立凭据

**决定**

- 读取面（`/kb/*`、`/skill.md`）：`requireToken` **默认关**，用户可在设置页打开；
- 管理面（`/api/*`）：**永远**要 admin 凭据（`api-token`，只以 `HttpOnly; SameSite=Strict` cookie 交给同源页面；界面不展示、不可复制），CLI 读文件带 `X-KB-Admin`；
- `/api/*` 还要求 `Sec-Fetch-Site: same-origin` 或 `Origin: <自己>`；
- **硬不变式**：绑定非回环地址时 `requireToken` 强制为开，CLI 与设置页都拒绝“局域网 + 无 token”。

**理由**

- “双击即用”是这个产品的前提。强制每个用户先去配 token、再粘给 agent，是第一公里就劝退；
- 无 token 的实际暴露面很窄：网页读不到（无 CORS + Host/Origin/Sec-Fetch-Site 校验），代价只是“本机其他程序能读”；
- “配置接口不能暴露给 agent”不能只靠“skill.md 里不提”，那是约定不是防线。admin 凭据分离让它变成**结构性**保证：agent 那把读 token 打不开 `/api/*`。

**代价（接受）**：多一个文件、多一次 cookie 下发；`/api/*` 不能再用 curl 随手调（要带 `Origin`），调试稍麻烦。

**重新考虑的条件**：出现“多人共用一台机器”的需求（那时要真权限，按 ADR-008 推开）。

## ADR-016 前端：Vite + Vue 3 + Tailwind v4 + Reka UI

**决定**：`web/` 用 Vite + Vue 3 + TS + Tailwind CSS v4 + `reka-ui`（无样式交互原语）+ `@iconify-json/lucide`。产物 `//go:embed` 进二进制。

**理由**

- 参考项目（fontcover-v2）就是 Tailwind + `@nuxt/ui`，视觉语言可以对齐，但 `@nuxt/ui` 绑 Nuxt（要 SSR），我们是纯静态 SPA，不带它；
- 只要“好看”，不要“后台管理系统脸”：Element / Naive / Ant 的默认观感与这个产品不搭，且整包体积大；
- Reka UI 只解决焦点陷阱、弹出层定位、无障碍这些**难写但没设计价值**的部分，视觉仍由自己的 token 控制。

**禁止**：SSR / Nuxt、CSS-in-JS、`innerHTML` 渲染用户内容、组件里裸 `fetch`。

## ADR-017 读取 skill 与写作 skill 分成两份，分开安装

**决定**：`/skill.md`（教 agent **怎么读**）与 `authoring.md`（教 AI **怎么写**）是两份独立文件、独立版本、在 UI 里两个独立安装按钮，落到不同的 skill 目录（`kb-lite` / `kb-lite-authoring`）。

**理由**：合成一份会让 agent 在“我只是想查点东西”的时候也照写作规范去动用户的文件。而我们**没有写接口**，它只会去改文件系统。读与写是两种意图，就该是两把钥匙。

## ADR-018 记录文件固定在配置目录，用户不选它的位置

**决定**：`index.db` 永远等于 `<配置目录>/index.db`。设置页与向导不再提供「记录文件位置」，
`serve --db` 与 `settings --db` 也去掉了。老 `config.json` 里写的别处一概忽略。

**理由**

1. 它只是缓存（ADR-003）。为一个「随时可以删」的文件提供路径输入框，收益是零，
   代价是让每个用户都要面对一个自己没有立场判断的技术选项。
2. 允许分居会造出「config 指向 A、缓存落在 B」的部署：删缓存时删错地方、搬机器时只搬了一半。
   两者同目录之后，「复制这个目录」就是完整的一次搬家。
3. 缓存路径一旦可配，就要处理「旧位置的文件怎么办」（搬？删？两份？），而它本来就是可重建的。

**推论**：`/api/status` 仍然回 `dbPath`（只读展示）并新增 `configDir`，界面只显示不编辑。
`POST /api/settings` 不再接受 `dbPath`；旧客户端带上它不报错，只是被忽略。

**没做的部分**：让用户选「这个用户专用 / 这台设备共用」。配置目录在进程启动时就定了，
UI 改它必须先写一个指针文件再重启进程；设备级还要写 `C:\ProgramData` 并显式改 ACL，
否则第二个用户打不开。要做得一次做全，见 docs/06 §5.1。
