# 00 · 定位与边界

## 一句话

把一个或多个 **markdown 目录**变成 **agent 可以直接 curl 的只读知识库**，检索质量靠一套设计过的打分机制（不用向量），服务端自带写给 agent 的使用说明。

## 目标用户

两类，按优先级排：

1. **“我想让自家 agent 读到我的知识库”的个人用户。**
   已经在用 Obsidian / VS Code / 某个 wiki 整理了大量 markdown；有一个 chatbot、harness、脚本或自动化流程需要查这些内容。
他们不懂（也不想懂）RAG、向量库、embedding 模型；不想为“让 AI 读我的知识库”注册云服务。
    其中一部分人**完全不懂代码**。他们需要图形界面。

2. **“一台机器跑服务，几个人往里加内容”的小团队。**
   不做账号权限，多端同步与冲突交给 `git`（在用户自己的编辑器里做，kb-lite 不碰 `.git`）。

## 三句话的价值观

1. **目录即真相。** 索引是可重建的缓存；删掉它不丢任何资料。任何时刻用 `vim` 改一个 `.md`，重新切片就能被看到。
2. **不联网。** 不调 LLM，不要 embedding，不需要 API key。开销应该是毫秒级的字符串匹配，不是一次模型调用。
3. **接口是为 agent 设计的，不是为人类聊天窗口设计的。**  返回值的大小、结构、错误形态都以“模型下一步要做什么”为准。

## 差异化（按重要性排序）

| 维度 | 我们的做法 | 为什么这算差异 |
|---|---|---|
| **检索协议** | 两段式：`search` 只回候选（标题/摘要/文本目录），`section` 按编号或标题二次定位。目录里带每节字数、标出空节 | 现有同类要么直接回片段，要么回文件级命中。这套协议是在真实使用里调出来的，直接决定了 agent 会不会白跑工具调用 |
| **零 LLM / 零依赖** | 纯字符串匹配打分；排序规则可解释、可 `--explain` | 同类项目普遍要么要 embedding 模型，要么要 LLM 跑后台维护 |
| **中文优先** | 关键词拆分带 CJK bigram 辅助匹配；全角/百分号/转义的标题归一化 | 同类几乎没有中文优化 |
| **部署形态** | 一个常驻 daemon + 纯 HTTP；多个进程共享同一份索引 | 大量同类是 MCP stdio，每个客户端各 spawn 一份，天然做不到“多进程共享” |
| **自带使用说明** | `GET /skill.md` 与工具行为同源生成 | 用户不需要理解检索策略，把这段文本塞给 agent 就能用对 |

## 明确不做

这些是**主动放弃**的，写在这里是为了之后的实现者不要顺手加回来：

- ❌ 向量检索 / embedding / 语义相似度（见 [10-decisions](./10-decisions.md#不做向量检索)）
- ❌ 写入 API（agent 只能读；改文件是人和 git 的事）
- ❌ 账号、权限、多用户租户
- ❌ PDF / docx / 网页抓取。只吃 `.md` 与 `.txt`，其余让用户自己转。我们能做的是把“该转成什么样”写清楚（[authoring-template](./authoring-template.md)），而不是自己去解析这些格式
- ❌ 后台常驻的维护 agent（自动打标签、校验事实、生成摘要之类）
- ❌ 云同步 / 托管服务
- ❌ 内置 LLM 问答。kb-lite 只负责“让别的 agent 查得准”，不负责回答

## 与“维基农场”的关系

kb-lite 的切片器与打分器源自一个维基农场的知识库（`slice.ts` / `searchRank.ts`，跑在一个 Node 服务里），那套规则已经被真实使用调教过多轮。

**但不能直接复用那份代码**：它是 TypeScript，复用它就意味着每个用户都得装 Node，或者接受 80–110 MB 的单文件产物。按“对用户影响最小”的原则，本地版用 **Go** 重写为静态二进制（见 [ADR-013](./10-decisions.md#adr-013-服务端用-go)）。

于是“线上版与本地版共用同一份实现”改成了“**共用同一份规格 + 同一份排序快照**”：

- 规格 = [02](./02-slicing.md) / [03](./03-search.md)，逐字实现；
- 快照 = `internal/core/testdata/rank/*.json`（查询 → 期望顺序），**线上版也必须跑它**。共享代码只保证“同样的 bug”，共享快照才保证“同样的正确”。

移植时**必须改**的地方见 [03-search](./03-search.md#与线上版的三处差异)。
